# INIT — поднять проект из шаблона (инструкция для Claude)

> Это **исполняемый чеклист для Claude**, не для пользователя. Пользователь говорит одной
> фразой: «инициализируй проект из шаблона» / «выполни INIT.md» — и Claude проходит шаги
> ниже. Шаблон уже должен быть скопирован в корень нового проекта (или Claude копирует на
> шаге 1, если дан путь-источник).
>
> **Порядок принципиален:** сначала выясняем, **что строим** (шаг 2), и только потом
> заполняем шаблон. Плейсхолдеры вроде стека и архитектуры после интейка уже известны —
> спрашивать их отдельно значит спрашивать дважды.

## Шаг 0 — режим работы
Это разовый бутстрап. Действовать аккуратно: ничего необратимого без подтверждения. После
завершения предложить удалить `INIT.md` и (по желанию) `README.md`.

## Шаг 1 — убедиться, что файлы шаблона на месте
В корне проекта должны быть: **`AGENTS.md`** (канон кросс-AI правил), `CLAUDE.md`, `.claude/`,
`.github/`, `planning/`, `docs/`, `memory-seed/`, `tools/` (референс-харнесс UI-аудита
`tools/ui-audit/`). Если их нет, а пользователь дал путь к шаблону — скопировать оттуда.

> **Три файла-входа, три хоста.** `AGENTS.md` — источник истины, автозагружается Harvi Code.
> `CLAUDE.md` — адаптер Claude Code, тянет канон через `@AGENTS.md`.
> `.github/copilot-instructions.md` — адаптер Copilot (имя обязано быть именно таким, иначе
> автозагрузки нет). Раскладка обоснована в `docs/adr/0001-agents-md-canon-without-ai-layer.md`.

## Шаг 2 — ИНТЕЙК: выяснить, что строим (ТЗ + спецификация + визуалы)

**Это главный шаг, и он идёт до подстановки плейсхолдеров.** Методика —
скил [`.claude/skills/spec-intake/SKILL.md`](.claude/skills/spec-intake/SKILL.md), вопросы —
[`docs/INTAKE_QUESTIONNAIRE.md`](docs/INTAKE_QUESTIONNAIRE.md), запуск в Claude Code —
`/spec-intake`, в Copilot — `/spec-intake`, в Harvi Code — открыть файл скила по пути.

**2.1. Определить вход** (первый сработавший выигрывает; пользователь может переопределить):

| Вход | Признак | Что происходит |
| --- | --- | --- |
| **docs-first** | В `docs/` уже лежат ТЗ / спека / PRD / бриф | Читаем целиком, раскладываем по нашим разделам; интервью — только добивание пробелов |
| **reference-first** | Даны ссылки на сайты/репозитории/конкурента, скриншоты, макеты | Разбираем референс, **выводим** черновик требований, подтверждаем вопросами |
| **questionnaire-first** | Нет ничего | Полный опросник с нуля |

Объявить выбранный вход вслух и сказать, чем он обернётся по объёму вопросов.

**2.2. Провести интервью** — по скилу `grill-with-docs`: **один вопрос за раз**, само-ответ
из репозитория/референса там, где ответ выводится. Анкету списком не вываливать.
Обязательны на **любом** входе:

- **прошлый опыт двумя раздельными вопросами** — что взлетело и что **не** взлетело
  (про неудачный опыт не рассказывают, если не спросить прямо);
- **визуалы** — минимум схема главного сценария и схема архитектуры.

**2.3. Записать три артефакта** (во всех трёх входах — одни и те же, различается только
объём интервью):

| Артефакт | Слой |
| --- | --- |
| [`docs/TZ.md`](docs/TZ.md) | что и зачем: цель, пользователи, scope/не-scope, сценарии, требования с проверяемым критерием, НФТ, ограничения, критерии приёмки, риски |
| [`docs/SPEC.md`](docs/SPEC.md) | как: архитектура, стек и обоснование, модули, данные, интеграции, окружения, тестирование, релиз, **опыт и грабли**, **handoff в планирование** |
| [`docs/VISUALS.md`](docs/VISUALS.md) | схемы и референсы — **единственный** визуальный артефакт, переписывается на месте, дублёров не заводить (ADR-0004) |

Пробелы помечать `> TODO(пользователь):` — **не выдумывать**. Термины → `CONTEXT.md`,
сокращения → `docs/GLOSSARY.md`, необратимые решения → `docs/adr/`, отложенное →
`planning/BACKLOG.md`.

> Пропускать шаг 2 можно, только если пользователь **явно** отказался от интейка. Тогда
> сказать вслух: генеральный план будет строиться без спецификации, и это его решение.

## Шаг 3 — плейсхолдеры: вывести, а не переспрашивать

После шага 2 бóльшая часть значений уже известна. **Сначала вывести из `docs/`, показать
пользователю на подтверждение одним сообщением, и только потом спрашивать недостающее.**

**Выводится из артефактов интейка (показать на подтверждение, не спрашивать заново):**

- `{{PROJECT_NAME}}` — из `docs/TZ.md` §1
- `{{STACK}}` — из `docs/SPEC.md` §2
- `{{ARCH_OVERVIEW}}` — из `docs/SPEC.md` §1 (сжать до 3–6 строк)
- `{{RUN_COMMAND}}`, `{{TEST_COMMAND}}` — из `docs/SPEC.md` §1 и §7
- `{{PROJECT_GOAL}}`, `{{SUBSYSTEM_1/2}}`, `{{KEY_DECISION_OR_CONSTRAINT}}`,
  `{{MILESTONE_1/2}}` (в `00_GENERAL_PLAN.md`) — из `docs/TZ.md` §1, §3 и `docs/SPEC.md` §3

**Спросить придётся (в артефактах интейка этого нет) — одним сообщением:**

- Профиль пользователя для seed-памяти: `{{USER_ROLE}}`, `{{USER_EXPERTISE}}`,
  `{{LANGUAGE_PREF}}`, `{{PREF_1}}`, `{{PREF_2}}`
- `{{TMP_DIR}}` — доп. каталог в `.claude/settings.json`
- `{{YYYY-MM-DD}}` — сегодняшняя дата (в `INDEX.md`-файлах)

**Условный блок — спрашивать, только если применимо:**

- Если есть **длительные прогоны** (сборка/пайплайн/тренировка): `{{PRIMARY_LOG_PATH}}`,
  `{{VERBOSE_LOG_PATH}}`, `{{LOG_NOISE_FILTER_REGEX}}`, `{{PIPELINE_STAGES}}`,
  `{{PROJECT_ERROR_SIGNALS}}`, `{{DOMAIN_SPECIFIC_SIGNAL}}`, `{{PROJECT_IMMEDIATE_SIGNAL}}`,
  `{{ARCH_BOUNDARY_1}}`, `{{ARCH_BOUNDARY_2}}`.

- Если ведётся **лог UI-действий** (для `/bug-intake`): `{{ACTIONS_LOG_PATH}}`,

- Если нужен **доменный субагент**: `{{DOMAIN}}`, `{{KEY_MODULES}}`, `{{ENTRYPOINT}}`,
  `{{CONTRACTS}}`, `{{PRIMARY_FILE}}`, `{{ORCHESTRATION_FILE}}`, `{{CONTRACTS_FILE}}`.
  Иначе — оставить `domain-dev.agent.md` как пример или удалить.
- Если есть **UI для аудита**: см. шаг 4 (`tools/ui-audit/`).

Незаполненные необязательные плейсхолдеры можно оставить как явные TODO — но сообщить о них.

## Шаг 4 — стековый профиль

Стек известен из `docs/SPEC.md` §2. Подобрать профиль и **предложить** соответствующие
действия. **Ничего не удалять без явного подтверждения пользователя.**

| Профиль стека | Инструкции оставить | Инструкции удалить/не нужны | `tools/ui-audit/` |
| --- | --- | --- | --- |
| Python (сервис, CLI, данные) | `python` | `typescript`, `react`, `react-native`, `swift` | удалить, если нет десктоп-UI |
| Веб на React | `typescript`, `react` | `python`, `swift`, `react-native` | не подходит: удалить или завести web-`IUiDriver` |
| React Native | `typescript`, `react-native` (+`react` — общие правила) | `python`, `swift` | не подходит: удалить или завести мобильный `IUiDriver` |
| Нативный iOS | `swift` | `python`, `typescript`, `react`, `react-native` | не подходит: удалить или завести `IUiDriver` под XCUITest |
| Бэкенд на TypeScript | `typescript` | `react`, `react-native`, `swift`, `python` | удалить |
| Десктоп (WinUI и др.) | по языку | остальные | **оставить и заполнить** `AuditConfig` в `tools/ui-audit/Program.cs` |
| Другое | `general-code` + свой файл из `_TEMPLATE.instructions.md` | — | по наличию UI |

Правила профиля:

- **`general-code.instructions.md` и `ponytail.instructions.md` остаются всегда** — они
  tech-agnostic.
- Стек не покрыт готовым файлом → скопировать `.github/instructions/_TEMPLATE.instructions.md`,
  задать `applyTo`-глоб под язык и заполнить. Файл `python.instructions.md` — **один из
  вариантов, а не дефолт**.
- В `CLAUDE.md` плейсхолдер `{{LANGUAGE}}` заменяется на имя выбранного файла инструкций
  (или на список, если языков несколько).
- `tools/ui-audit/` — референс-харнесс системы `auditing-ui` (Phase 3 «краул») на WinUI/FlaUI.
  Для web/RN/iOS он не подходит: либо удалить, либо реализовать новый драйвер за интерфейсом
  `IUiDriver` (см. `.claude/skills/auditing-ui/SKILL.md`, `tools/ui-audit/README.md`).
  Если UI-аудит не нужен вовсе — можно удалить и скил `auditing-ui`, и команду `/audit-ui`.
- `{{RUN_COMMAND}}` / `{{TEST_COMMAND}}` из шага 3 — те же команды, которыми пользуется
  скил `run`. Если их нет — так и записать, а не выдумать правдоподобные.

## Шаг 5 — подставить значения
Заменить плейсхолдеры по всем файлам, **КРОМЕ механики команд** (НЕ трогать):

- **Переменные Copilot-промптов** — любые `{{camelCase}}` в `.github/prompts/*.prompt.md`
  (`{{planTitle}}`, `{{planGoal}}`, `{{planSlug}}`, `{{problem}}`, `{{symptom}}`,
  `{{entryMode}}`, `{{varOne}}`, `{{varTwo}}`, `{{var}}`): их подставляет Copilot при вызове
  команды, а не мы. **Признак: имя в camelCase, а не в UPPER_SNAKE_CASE.**
- любые файлы `_TEMPLATE.*` и `skills/_TEMPLATE/` — оставить как скелеты
- упоминания `{{var}}`/`{{...}}` в `README.md` как примеры синтаксиса — не трогать
- перечни плейсхолдеров в этом файле (`INIT.md`) — он всё равно удаляется в конце

После замены: `grep -rn "{{" .` — показать оставшиеся плейсхолдеры (должны остаться только
механика команд, `_TEMPLATE`-скелеты и осознанно отложенные TODO). Сообщить список пользователю.

## Шаг 6 — установить seed-память
По `docs/MEMORY_GUIDE.md`:
1. Определить per-project memory-каталог `~/.claude/projects/<derived-from-path>/memory/`
   (вывести из абсолютного пути проекта; если непонятно — взять самый свежий каталог в
   `~/.claude/projects/` после первого открытия проекта).
2. Скопировать туда содержимое `memory-seed/` (`MEMORY.md`, `user-profile.md`,
   `working-rules-limit-discipline.md`, `_TEMPLATE.memory.md`).
3. В скопированном `user-profile.md` проставить значения профиля из шага 3.
4. Сообщить пользователю полный путь установленной памяти.

> Память есть **только у Claude Code**. Harvi Code и Copilot её не читают — не ссылаться на
> неё в артефактах, которые они будут открывать.

## Шаг 7 — выбрать хосты и подчистить
Спросить, в каких хостах работает пользователь (Claude Code · Harvi Code · Copilot · смешанно).

**По умолчанию НИЧЕГО не удалять** — неиспользуемые адаптеры безвредны, а хост может добавиться
позже. Удалять только по явному подтверждению пользователя:
- не использует Copilot → `.github/prompts/`, `.github/agents/`,
  `.github/copilot-instructions.md`;
- не использует Claude Code → `.claude/commands/`, `.claude/agents/`, `CLAUDE.md`;
- **`AGENTS.md`, `.claude/skills/` и `.github/instructions/` не удалять никогда** — это канон и
  host-neutral склад методики, их читают все хосты.

Дополнить `.gitignore` нового проекта строками из `gitignore.snippet` (создать `.gitignore`,
если нет). Среди них — `AGENTS.local.md` (личный локальный оверлей Harvi Code).

**Установить pre-commit hook** (блок прямых коммитов в `main`/`master`):

```bash
cp githooks/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

Windows без Git Bash — то же в PowerShell (бит исполняемости не нужен):

```powershell
Copy-Item githooks/pre-commit .git/hooks/pre-commit -Force
```

**Проверить, что хук работает, а не просто лежит на месте** — иначе правило записано, но не
исполняется:

```bash
git switch main && .git/hooks/pre-commit; echo "exit=$?"   # ожидаем exit=1 и сообщение об ошибке
```

Полосы доверия, конвенция веток и review-handoff — в `AGENTS.md` (раздел «Полосы доверия»);
чеклист консервативной полосы — `.github/prompts/ai-branch-workflow.prompt.md`.

## Шаг 8 — финал и передача в планирование
- Кратко отчитаться: что заполнено, что осталось `TODO(пользователь)` в `docs/TZ.md` и
  `docs/SPEC.md`, куда установлена память, какой стековый профиль выбран, какие ADR заведены.
- **Предложить построить генеральный план** — и сделать это по протоколу handoff из
  `docs/SPEC.md` §11: оценить работу по рубрике, выдать «модель + эффорт + обоснование»,
  **остановиться и ждать «продолжить»**. Не начинать план до ответа пользователя.
  В хостах без переключения модели пауза не запрашивается — сказать, что это рекомендация.
- Предложить удалить `INIT.md` (и при желании `README.md`) — это бутстрап-артефакты.
- НЕ запускать долгие процессы и не делать коммитов без явной просьбы.
