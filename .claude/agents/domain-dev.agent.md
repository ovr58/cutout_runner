## Workflow

1. Прочитать затронутый файл целиком ДО правок (Read, не Grep-сниппет).
2. Внести минимальное изменение (1 задача = 1 правка; без рефакторинга «заодно»).
3. После правки — проверить компиляцию/типы/линтер проекта.
4. Прогнать релевантные тесты: {{TEST_COMMAND}}.
5. Не запускать долгие end-to-end прогоны ради проверки мелкого фикса — unit-тест или ручное
   воспроизведение условия.

## Правила

- Уважать архитектурные границы (см. `AGENTS.md` → «Работа с кодом»).
- Логировать только через логгер проекта; никаких `print`/`console.log` в проде.
- Не вносить секреты в код/git.
- Докладывать честно: если тест упал — показать вывод; если шаг пропущен — сказать.
