# Интейк проекта: ТЗ + спецификация + визуалы

Ведёт проект от «хочу приложение» до трёх артефактов в `docs/`, годных как вход для
генерального плана. **Методика — скил [`spec-intake`](../skills/spec-intake/SKILL.md);
эта команда только запускает её и держит порядок шагов.**

Вход: `$ARGUMENTS` — необязательный явный режим (`docs` · `reference <ссылки>` · `scratch`).
Если не задан — определить вход самому по шагу 0 скила.

## Шаги

1. **Определить вход** (скил, шаг 0): docs-first · reference-first · questionnaire-first.
   Объявить выбор вслух и сказать, чем он обернётся для объёма интервью.
2. **Провести интервью** по [`docs/INTAKE_QUESTIONNAIRE.md`](../../docs/INTAKE_QUESTIONNAIRE.md)
   в режиме `grill-with-docs`: **один вопрос за раз**, само-ответ из репозитория/референса
   там, где ответ выводится. Анкету списком не вываливать.
   Обязательны на любом входе: блок **О** (удачный и **неудачный** опыт — раздельно) и
   блок **V** (визуалы).
3. **Записать три артефакта:** [`docs/TZ.md`](../../docs/TZ.md) ·
   [`docs/SPEC.md`](../../docs/SPEC.md) · [`docs/VISUALS.md`](../../docs/VISUALS.md).
   Пробелы — `> TODO(пользователь):`, не выдумка. Визуальный артефакт **один**, переписывается
   на месте (ADR-0004).
4. **Развести по канону:** термины → `CONTEXT.md` · сокращения → `docs/GLOSSARY.md` ·
   необратимые решения → `docs/adr/` · отложенное → `planning/BACKLOG.md`.
5. **Handoff:** исполнить протокол из `docs/SPEC.md` §11 — оценить работу по рубрике, выдать
   «модель + эффорт + обоснование», **остановиться и ждать «продолжить»**. Не начинать
   генеральный план до ответа.
6. **Отчитаться:** что заполнено, сколько осталось `TODO(пользователь)`, какие ADR заведены.
   Коммитов и пушей без явной команды не делать.

> Если проект поднимается из шаблона — эта команда исполняется **до** подстановки
> плейсхолдеров: после интейка имя проекта, стек и обзор архитектуры уже известны из
> `docs/SPEC.md` и повторно не спрашиваются.
