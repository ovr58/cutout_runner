# UI-аудит приложения (adequacy, не liveness)

Оркестрирует сквозной аудит UI по методике скила **`auditing-ui`** — открой его `SKILL.md` и
следуй ему (карта переходов → демо-краул со скриншотами → пакетный vision-обзор → семантическая
сверка → findings). Команда — тонкая обёртка над скилом: скил несёт метод, команда прогоняет его на
этом проекте и оформляет результат.

Вход: `$ARGUMENTS` — необязательный список экранов (по умолчанию — все).

## Референс-реализация (argus, WinUI)

- Драйвер/краулер: `argus.ui/tools/Argus.Ui.Audit/` (консоль, FlaUI/UIA3; `IUiDriver` seam).
  **Запускать собранный `argus-ui-audit.exe`, а НЕ `dotnet argus-ui-audit.dll`**: DPI-манифест
  (`app.manifest`, PerMonitorV2) вшит в apphost-`.exe`; через `dotnet <dll>` DPI-режим наследуется от
  `dotnet.exe` (System-aware) → скриншоты на HiDPI усекаются до левых ~40%. Контроль: размер первого
  кадра ≈ физическому разрешению монитора (напр. 3872×2072), а не ~1549px.
- Демо-режим: `ARGUS_UI_DEMO=1` (фейки `Services/Demo/*`, переключатель в `App.ConfigureServices`).
- exe: `argus.ui/src/Argus.Ui/bin/x64/Debug/net8.0-windows10.0.19041.0/Argus.Ui.exe`
  (сборка — по памяти `argus-ui-build`: DOTNET_ROOT, `-p:Platform=x64`, ASCII TEMP).
- Статическая карта/выхлоп: `argus.ui/audit/` (`ui-transition-tree.md`, `runs/<ts>/`).
- Другой стек (web) — добавляется новой реализацией `IUiDriver`, шаги ниже не меняются.

## Шаги

1. **Вопросы при запуске.** Задай пользователю набор из `auditing-ui/questions.md` (одним
   `AskUserQuestion`, только значимые; дефолты назови). Учти `$ARGUMENTS` как scope.
2. **Демо-режим готов?** Убедись, что демо-переключатель есть и UI офлайн рендерит все экраны
   (иначе краул недетерминирован). Нет — сначала завести seam (скил, шаг 1).
3. **Статическая карта.** Свежая ли `ui-transition-tree.md` (экран→контрол→команда→CORE-вызов +
   нав-граф + golden-пути)? Устарела — обнови по XAML+ViewModels.
4. **Краул.** Собери и запусти харнесс аудита (демо-режим), обойди экраны/golden-действия, снимок
   каждого состояния → `runs/<ts>/crawl.json` + `screens/*.png`. Проверь покрытие против карты.
   Напоминание из скила: перед КАЖДЫМ снимком окно на передний план + развернуть; титульные
   кнопки/нативные пикеры — деньить по AutomationId; краулер запускать через `.exe` (DPI-манифест),
   не `dotnet <dll>` — иначе скриншоты обрежутся на HiDPI (см. Референс-реализацию выше). Краулер
   само-проверяет DPI на старте: увидел варн про не-PerMonitorV2 (или блок `dpi`/`frameCheck` в
   `crawl.json` сигналит обрезку) — перезапусти через `.exe`.
5. **Vision-обзор (один дешёвый fan-out).** Спавни **один** субагент `model: sonnet` по **всем**
   скриншотам прогона сразу (рубрика `auditing-ui/rubric.md` + назначение экранов + действие на
   каждый снимок). Не по одному снимку — дисциплина затрат (`docs/WORKING_RULES.md` §2).
6. **Семантическая сверка (ты).** По каждой функции: верный ли CORE-путь, отражает ли результат
   назначение экрана, корректно ли взаимодействует с соседями по golden-путям. Плюс дефекты
   accessibility-имён из `crawl.json` (сырые дампы объектов, склеенные/пустые/`"?"` имена).
7. **Findings → план фикса.** Слей vision + семантику + accessibility, отранжируй по severity,
   удали дубли. Оформи записью в `planning/BACKLOG.md` (готовый промпт для `/plan-new`) — это и есть
   результат аудита; обнови `planning/INDEX.md` при заведении.

## Гигиена

Долгие сборки/прогоны — по `planning/reference/CLAUDE_MONITORING_GUIDE.md` (ScheduleWakeup, не
Monitor). Один vision-спавн, а не поток. Отчёт — только новое; падения — сразу.
