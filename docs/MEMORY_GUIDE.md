# Долгая память Claude — гайд

Claude Code держит **персистентную файловую память** для проекта. Она живёт **вне
репозитория** и переживает сессии. Этот гайд описывает формат и как установить стартовый
набор из `memory-seed/`.

> **Это возможность только Claude Code.** У Harvi Code и Copilot долгой памяти проекта нет —
> ни автоматической загрузки, ни хранилища. Не ссылайся на память в артефактах, которые будут
> читать они: для них такой ссылки не существует. Опциональная замена — `.ai-memory/`,
> см. раздел «Переносимая память» в конце.

## Где живёт память

```
~/.claude/projects/<derived-from-path>/memory/
├── MEMORY.md          ← индекс: одна строка-указатель на каждый факт
├── <slug-1>.md        ← один факт = один файл
├── <slug-2>.md
└── …
```

`MEMORY.md` загружается в контекст каждой сессии (только индекс, не тела). Тела отдельных
файлов всплывают по релевантности при «вспоминании».

### Как вычислить `<derived-from-path>`

Имя каталога Claude Code выводит из абсолютного пути проекта, заменяя разделители и
небуквенно-цифровые символы на дефис `-`. Пример:

```
проект:   d:\work\my-app\backend
каталог:  ~/.claude/projects/d--work-my-app-backend/memory/
```

Проще всего: **открыть проект в Claude Code один раз** — каталог
`~/.claude/projects/<...>/memory/` создастся сам. Затем найти его (например по самой свежей
папке в `~/.claude/projects/`) и положить туда seed-файлы.

## Формат файла памяти

```markdown
---
name: <short-kebab-case-slug>
description: <одна строка — по ней решается релевантность при вспоминании>
metadata:
  type: user | feedback | project | reference
---

<сам факт. Для feedback/project — далее строки **Why:** и **How to apply:**.
Связывай родственные памяти ссылками [[their-name]].>
```

- `[[name]]` — ссылка на другую память по её слагу `name`. Ссылайся свободно; `[[name]]`
  на ещё не созданную память — это нормально, помечает «стоит завести».

### Типы памяти

| type | Что хранит |
| --- | --- |
| `user` | Кто пользователь: роль, экспертиза, предпочтения. |
| `feedback` | Как Claude следует работать — правки и подтверждённые подходы. С **Why:**. |
| `project` | Текущая работа, цели, ограничения, НЕ выводимые из кода/гита. Относительные даты → абсолютные. |
| `reference` | Указатели на внешние ресурсы (URL, дашборды, тикеты). |

## Правила ведения

- **Один факт — один файл.** После создания файла — добавить строку-указатель в `MEMORY.md`
  (`- [Заголовок](file.md) — крючок`).
- **Не дублировать.** Перед записью проверить, нет ли файла, уже покрывающего тему — обновить
  его, а не плодить копию. Ошибочные памяти — удалять.
- **Не сохранять то, что и так в репо** (структура кода, прошлые фиксы, история гита,
  `CLAUDE.md`) или что важно лишь для текущего диалога.
- **Память — снимок на момент записи.** Если память называет файл/функцию/флаг — проверить,
  что он ещё существует, прежде чем рекомендовать.

## Установка seed-памяти (из `memory-seed/`)

1. Открыть новый проект в Claude Code (создастся memory-каталог — см. выше).
2. Скопировать всё из `memory-seed/` в `~/.claude/projects/<derived>/memory/`.
3. Открыть `user-profile.md` и заполнить плейсхолдеры (роль, стек, предпочтения).
4. Проверить, что `MEMORY.md` ссылается на скопированные файлы.

Дальше Claude ведёт память сам по правилам выше.

## Переносимая память `.ai-memory/` (опционально)

Для проектов, где Harvi Code — основной хост, а не вспомогательный. Каталог `.ai-memory/` в
корне проекта, тот же формат (индекс `MEMORY.md` + файл на факт), в git **не попадает**
(`.gitignore`).

**Честно о разнице в гарантиях:**

| | Память Claude Code | `.ai-memory/` |
| --- | --- | --- |
| Где | `~/.claude/projects/<derived>/memory/` (вне репо) | `.ai-memory/` в корне проекта |
| Кто загружает | харнесс, автоматически | **никто** — агент обязан открыть файл сам |
| Гарантия | индекс в контексте каждой сессии | только если правило записано в `AGENTS.md` **и** агент ему следует |

То есть `.ai-memory/` — не эквивалент, а более слабый суррогат: механизм «агент читает файл по
пути», а не встроенная память.

**Как включить** (по умолчанию выключено — не объявляй правило, которого не будет исполнения):

1. Создать `.ai-memory/MEMORY.md` — индекс в том же формате.
2. Добавить в `AGENTS.md` строку вида: «Долгая память проекта — `.ai-memory/MEMORY.md`;
   прочитай индекс в начале сессии, факты — по релевантности; новый факт — файл + строка в
   индексе».
3. Убедиться, что `.ai-memory/` есть в `.gitignore` (строка уже в `gitignore.snippet`).

**Не смешивать с памятью Claude Code.** Это два независимых хранилища; синхронизации между
ними нет, и `.ai-memory/` не даёт доступа к приватной памяти Claude.
