# ADR-0002: Полоса доверия определяется моделью (Opus), а не хостом

- **Status:** Accepted
- **Date:** 2026-08-26
- **Related:** `planning/active/cross-ai-rule-enforcement-harvi-opus_2026-08-26.md` (Р2, Р3);
  ADR-0001

## Context

До появления Harvi Code темплейт связывал доверие с **хостом**: Claude Code работал в
`claude/<slug>` и мёржил в main после self-review без ожидания апрува; Copilot работал в
`feature/`/`fix/`/`exp/` и мёржился только после ревью Claude и апрува пользователя.

Harvi Code ломает эту связку: это сторонний хост, но в нём доступен **Opus** — то есть та же
модель, которой темплейт доверяет надзорную функцию. Одновременно в Claude Code можно работать
на Sonnet — хосту темплейт доверяет, а модель при этом слабее надзорной.

Силы:

- Надзорной функцией пользователь назвал **главенство Opus над остальными моделями** — то есть
  свойство модели, а не свойство редактора.
- Контраргумент за привязку к хосту: доверие даёт не только модель, но и харнесс — consult-first
  скилы, долгая память, hooks, автозагруженные `docs/WORKING_RULES.md`. В Harvi этого нет.
- Контраргумент ослаблен решением ADR-0001: если `AGENTS.md` автозагружается, Harvi получает тот
  же свод правил, а скилы читает по пути. Разрыв в харнессе сокращается до отсутствия памяти и
  hooks.
- Привязка к хосту дала бы аномалию: Sonnet в Claude Code мёржит сам, Opus в Harvi — не может.

Дорого откатить: полоса доверия определяет, какие изменения попадают в `main` без второй пары
глаз. Ошибка обнаруживается не в момент принятия решения, а через накопленные непроверенные
мёржи; отмена задним числом требует аудита истории, а не правки документа.

## Decision

Право на self-review и мёрж определяется **активной моделью**, а не хостом.

- **Доверенная полоса — Opus (любой хост: Claude Code или Harvi).** Ветки `claude/<slug>` /
  `harvi/<slug>`, self-review разрешён, fast-merge в `main` сохраняется, планы без суффикса.
  Opus также обязан выступать ревьюером для консервативной полосы.
- **Консервативная полоса — любая не-Opus модель** (Sonnet, Copilot, DeepSeek и пр.). Ветки
  `feature/` / `fix/` / `exp/`, суффиксы планов `_harvi_`, `_copilot_`, `_claude_<model-slug>_`,
  self-approve запрещён, обязателен review-handoff и мёрж только после ревью Opus **и** явного
  апрува пользователя.
- **Fallback:** если хост не может подтвердить активную модель — консервативная полоса.
- **Хард-правило для всех полос:** прямых коммитов в `main`/`master` нет; пуш и деплой — только
  по явной команде пользователя.

Предложение удалить fast-merge целиком отклонено: заявленное противоречие с
`docs/WORKING_RULES.md` §7 мнимое — §7 регулирует внешние/публикующие действия (пуш, деплой), а
не локальный мёрж в `main`.

## Consequences

- Обязаны: объявлять активную модель в начале сессии — от этого зависит выбор полосы.
- Обязаны: `/review-branches` покрывает `harvi/*` и ветки консервативной полосы; пауза на смену
  модели запрашивается только там, где хост её поддерживает.
- Нельзя: считать Claude Code на Sonnet доверенной полосой только потому, что это Claude Code.
- **Известное ограничение:** правило машинно не проверяемо. Ни pre-commit hook, ни CI не знают
  активную модель — исполнение держится на самообъявлении и на ревью Opus. Это принято сознательно;
  изображать здесь гарантию нельзя.
- Разрыв в харнессе остаётся: Opus в Harvi не имеет долгой памяти и hooks. Если это на практике
  начнёт давать худшие ревью — решение пересматривается новым ADR, а не правкой этого.
