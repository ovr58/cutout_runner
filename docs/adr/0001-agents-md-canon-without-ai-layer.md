# ADR-0001: Канон кросс-AI правил — `AGENTS.md` + существующий `.claude/`, без слоя `.ai/`

- **Status:** Accepted
- **Date:** 2026-08-26
- **Related:** `planning/active/cross-ai-rule-enforcement-harvi-opus_2026-08-26.md` (Р1);
  отвергнутая альтернатива — `planning/active/cross-ai-template-upgrade_2026-08-26.md` §2

## Context

В темплейт добавляется третий хост — Harvi Code — к уже поддержанным Claude Code и Copilot.
Возник вопрос, где живёт канонический текст правил, команд и скилов.

Предложенная Harvi альтернатива: завести нейтральный слой `.ai/{commands,skills,agents,
memory-seed}` как канон, а `.claude/` и `.github/` превратить в адаптеры с маркером источника.
Это дало бы нейтральные имена и симметрию хостов.

Силы:

- **Исполняемость правила определяется автозагрузкой, а не раскладкой файлов.** Claude Code
  автообнаруживает `.claude/skills/`; Harvi и Copilot — **нет** ни для какого пути. Harvi в
  любом случае читает markdown по явно указанному пути.
- Следовательно, `.ai/skills/INDEX.md` и `.claude/skills/INDEX.md` для Harvi **равноценны по
  исполняемости**. Разница только в цене: третья копия ~20 скилов и 6 команд поверх уже
  существующих двух (`.claude/` + `.github/`).
- Генератор синхронизации отвергнут обеими сторонами как избыточная сложность → копии
  расходятся вручную.
- Три расходящиеся копии делают вопрос «какая из них правило?» неразрешимым.

Дорого откатить: как только адаптеры и десятки документов начинают ссылаться на канонические
пути, смена раскладки — это сквозная переработка ссылок во всех файлах темплейта и во всех
проектах, поднятых из него. Плюс решение будет переоткрываться каждой новой сессией любого
хоста, которая увидит имя `.claude/` и сочтёт его «чужим».

## Decision

Каноном кросс-AI политики становится корневой **`AGENTS.md`**; слой `.ai/` не заводится.

- `AGENTS.md` — единственный источник истины по кросс-AI правилам, автозагружается Harvi.
- `CLAUDE.md` остаётся реальным файлом (Claude Code не читает `AGENTS.md`) и подтягивает канон
  через `@AGENTS.md`-импорт, добавляя только Claude-native секции.
- `.github/copilot-instructions.md` — выжимка + ссылка на `AGENTS.md` (Copilot импортов не
  поддерживает, здесь краткое дублирование оправдано).
- **`.claude/` объявляется host-neutral складом методики для всех хостов.** Имя каталога — это
  артефакт автообнаружения Claude Code, а не признак принадлежности. `AGENTS.md` фиксирует это
  явным абзацем и направляет Harvi/Copilot читать `.claude/skills/INDEX.md` по пути.
- `memory-seed/` остаётся на месте, зеркал не заводится.

## Consequences

- Новых копий скилов и команд — **ноль**. Число расходящихся источников не растёт.
- Обязаны: держать в `AGENTS.md` явную оговорку про host-neutral `.claude/` — без неё имя
  каталога читается как «не моё» и правило перестаёт исполняться.
- Обязаны: любое правило, которое должен исполнять не-Claude хост, формулировать в `AGENTS.md`
  с явным относительным путём к файлу — автообнаружения там нет.
- Нельзя: обещать в документации, что Harvi «регистрирует» команды/скилы. Только явное чтение
  файла по пути.
- Цена: раскладка выглядит Claude-центричной. Принято сознательно — исполняемость важнее
  нейтральности имён.
- Этот ADR — готовый ответ на переоткрытие вопроса о `.ai/` следующей сессией любого хоста.
