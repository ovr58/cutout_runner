## V-01 — Главный сценарий

Что показывает: один вызов `POST /cutout` целиком, включая оба штатных исхода и оба отказа.

```mermaid
sequenceDiagram
    autonumber
    participant C as Вызывающий<br/>(Edge Function)
    participant N as nginx (TLS)
    participant S as cutout_runner<br/>(127.0.0.1)
    participant M as ONNX-сессия<br/>(в памяти)

    C->>N: POST /cutout<br/>Bearer + байты кадра
    N-->>C: 413 / 429 (тело велико / слишком часто)
    N->>S: тот же запрос на 127.0.0.1
    S-->>C: 401 (секрета нет ИЛИ он неверный — одинаково)
    S-->>C: 503 + Retry-After (очередь занята)
    S-->>C: 400 (тело не разбирается как изображение)
    S->>M: тензор 1×3×1024×1024
    M-->>S: логиты 1×1×1024×1024
    S->>S: сигмоида → маска → ресайз к W×H → альфа
    alt доля маски 1%…99%
        S-->>C: 200 image/png, ровно W×H
    else <1% или >99% — товара нет
        S-->>C: 204 без тела
    end
```

## V-04 — Конвейер выреза

Что показывает: превращение байтов кадра в байты выреза и точку, где рождается 204.

```mermaid
flowchart TD
    A["Байты кадра<br/>image/png или image/jpeg, W×H"] --> B{"Декодируется?"}
    B -- нет --> B4["400"]
    B -- да --> C["raw RGB, W×H<br/>сохраняется до конца как есть"]
    C --> D["Копия → ресайз 1024×1024<br/>нормировка ImageNet<br/>(mean .485/.456/.406, std .229/.224/.225)"]
    D --> E["ONNX: тензор 1×3×1024×1024"]
    E --> F["Логиты 1×1×1024×1024"]
    F --> G["СИГМОИДА<br/>(не min-max: на логитах она даёт 99,9% полутона)"]
    G --> H["Маска 0…1, 1024×1024"]
    H --> I{"Доля пикселей > 0,5"}
    I -- "<1% или >99%" --> I2["204 — товара нет<br/>(штатный исход: слой есть у 4 макетов из 34)"]
    I -- "1%…99%" --> J["Ресайз маски Lanczos<br/>к ТОЧНЫМ W×H"]
    J --> K["Альфа-канал = маска×255<br/>+ исходный RGB из шага C"]
    K --> L["PNG, ровно W×H<br/>RGB пиксель в пиксель = исходник"]

    style G fill:#b45309,color:#fff
    style J fill:#b45309,color:#fff
    style I2 fill:#166534,color:#fff
```

> Оранжевым отмечены два шага, ошибка в которых **не видна на глаз** и всплывает уже на готовой
> карточке: неверная активация (`TZ.md` FR-04) и неточный размер маски (`TZ.md` FR-05).

## V-05 — Граница доверия

Что показывает: чего на машине сервиса **нет** — это и есть содержание решения
[ADR-0006](adr/0006-service-trust-boundary.md).

```mermaid
flowchart LR
    subgraph P["Родительский продукт"]
        EF["Edge Function"]
        DB[("База")]
        ST[("Хранилище")]
        K[("Ключи Supabase")]
    end

    subgraph H["Машина сервиса"]
        S["cutout_runner"]
        SEC[("Общий секрет<br/>ТОЛЬКО он")]
    end

    EF -- "байты кадра → байты выреза" --> S
    EF --- DB
    EF --- ST
    EF --- K
    S -.-x DB
    S -.-x ST
    S -.-x K

    style H fill:#0f2b46,color:#fff
```

> Пунктир с крестом — связи, которых **не существует и не должно появиться**. Взлом машины даёт
> кадры, которые через неё прошли, — и ничего больше. Ради этого свойства кадр и пересылается
> целиком, вместо ссылки на хранилище.

## V-06 — Состояния сервиса

Что показывает: почему `/health` бывает 503 и когда становится 200.

```mermaid
stateDiagram-v2
    [*] --> Старт
    Старт --> Отказ: нет CUTOUT_SECRET<br/>(процесс не стартует)
    Старт --> Loading: конфиг прочитан,<br/>сокет 127.0.0.1 слушает
    Loading --> Ready: сессия ORT создана (~5 с)
    Loading --> Отказ: весов нет / сессия не создалась
    Ready --> Ready: POST /cutout

    note right of Loading
        GET /health → 503
        {"status":"loading","ready":false}
        POST /cutout → 503
    end note

    note right of Ready
        GET /health → 200
        {"status":"ok","ready":true}
        ни версии, ни имени модели, ни путей
    end note

    Отказ --> [*]: ненулевой код выхода,<br/>systemd Restart=on-failure
```

## Референсы

Референс-приложений у проекта нет: контракт задан родительским продуктом, а не чужим
интерфейсом. Единственный внешний код, с которым сверялась реализация, — сессия
`birefnet_general` из `rembg` (источник входного размера 1024×1024 и нормировки ImageNet).
**Что берём:** размер входа и нормировку. **Что не берём:** min-max поверх сигмоиды —
обоснование в [`SPEC.md`](SPEC.md) §9.
