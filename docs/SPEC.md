## 1. Архитектура

Один процесс Node на выделенной машине. Он держит ONNX-сессию сегментации резидентно в памяти,
принимает **сырые байты кадра** по HTTP от единственного клиента и возвращает **тот же растр**
с наложенным альфа-каналом. Наружу процесс не выпущен: он слушает `127.0.0.1`, а TLS,
ограничение размера тела и ограничение частоты стоят в nginx перед ним. Состояния между
запросами нет — только загруженная модель.

- **Контекст системы** — схема [V-02](VISUALS.md#v-02)
- **Контейнеры** — схема [V-03](VISUALS.md#v-03)
- **Конвейер выреза** — схема [V-04](VISUALS.md#v-04)

**Точка входа:** [`src/main.ts`](../src/main.ts)

**Как запускается (прод):**

```
node dist/main.js
```

**Как запускается (разработка):**

```
npm run dev
```

**Как собирается:**

```
npm ci && npm run build
```

**Как тестируется:**

```
npm test
```

## 2. Стек и обоснование выбора

| Слой | Выбор | Почему именно он | Откатываемо? |
| --- | --- | --- | --- |
| Рантайм | Node 22 LTS | нативный ONNX Runtime доступен как npm-пакет; вызывающий и так живёт в JS-экосистеме | дорого |
| Язык | TypeScript, компиляция `tsc` в `dist/` | контракт из четырёх ответов и тензорные формы — там, где типы окупаются | легко |
| HTTP | `node:http`, **без веб-фреймворка** | два маршрута, тело — сырые байты; фреймворк добавит зависимостей больше, чем кода (Ponytail: stdlib раньше dep) | легко |
| Инференс | `onnxruntime-node` (нативный, **не** `-web`) | wasm-путь измеренно не работает: в изоляте инференс снимает супервизор | дорого — [ADR-0005](adr/0005-native-onnx-service-over-isolate.md) |
| Модель | `u2netp` (веса — по предварительному согласию авторов, разбор в README, раздел «Лицензии») | 0,55 с и 320 МиБ против 18,7–22,3 с и 6025 МиБ у `birefnet-general-lite`; кромка при этом хуже (6,2% полутона против 0,2–0,4%) и на 2 кадрах из 7 модель разваливается — размен принят решением владельца 2026-09-06 | высоко |
| Изображения | `sharp` (libvips) | декодирование PNG/JPEG, ресайз маски Lanczos и сборка RGBA — одной нативной зависимостью вместо трёх чистых JS | средне |
| Тесты | `node:test` (stdlib) | тест-раннер уже в рантайме; jest/vitest здесь ничего не добавляют | легко |
| Сборка/деплой | systemd + nginx на Ubuntu | машина уже существует и настроена; контейнер добавил бы слой без выгоды | легко |

### Рассмотренные альтернативы

| Вариант | Чем был привлекателен | Почему отвергнут |
| --- | --- | --- |
| Инференс в изоляте Supabase Edge Functions | ноль новой инфраструктуры, всё в одном месте | в изоляте доступен только однопоточный wasm; инференс **ни разу не завершился**, его снимал супервизор ([ADR-0005](adr/0005-native-onnx-service-over-isolate.md)) |
| Инференс в браузере пользователя | нулевая стоимость на нашей стороне | многопоточность требует заголовков изоляции источника; на iOS память бьёт жёстким отказом при инициализации |
| Генеративная модель вместо сегментации | «просто перерисовать товар на прозрачном фоне» | вернёт **новые** пиксели: товар сместится, и вместо «текст за курткой» получится двойной контур. Нужна альфа для **того же** растра |
| `u2netp` | быстрее | полутон на кромке 1,5–4,3% против 0,2–0,4%. Оставлен как запасной вариант, если понадобится скорость ценой кромки |
| Express/Fastify | привычно | два маршрута с сырым телом; фреймворк — чистый довесок |
| Ссылка на объект в хранилище вместо байтов кадра | меньше трафика | потребовала бы ключа к хранилищу на машине сервиса — ровно то, что запрещает [ADR-0006](adr/0006-service-trust-boundary.md) |

## 3. Модули и контракты

| Модуль | Ответственность | Что наружу (интерфейс) | Что внутри (скрыто) |
| --- | --- | --- | --- |
| `src/config.ts` | Прочитать и провалидировать окружение при старте | `loadConfig(): Config` — бросает, если нет `CUTOUT_SECRET` | имена переменных, умолчания, разбор чисел |
| `src/logger.ts` | Единственный способ писать в журнал | `log.info/warn/error(event, fields)` | формат строки, поток вывода |
| `src/auth.ts` | Доказательство права звать | `makeAuthorizer(secret): (header?: string) => boolean` | хэширование до фиксированной длины, `timingSafeEqual` |
| `src/model/session.ts` | Жизненный цикл ONNX-сессии | `createSegmenter(cfg): Promise<Segmenter>`; `Segmenter.run(input): Promise<Float32Array>`, `.inputSize` | опции сессии (арена, потоки), имена входа/выхода, форма тензора |
| `src/cutout/pipeline.ts` | Кадр → вырез / сэмплы маски или «выреза нет» | `computeCutout(bytes, segmenter, cfg): Promise<Buffer \| null>`, `computeMask(...): Promise<MaskSamples \| null>` | препроцесс, активация, ресайз маски, порог покрытия (одно на обе операции), сборка PNG |
| `src/cutout/mask.ts` | Чистая арифметика маски | `sigmoid`, `logitsToAlpha`, `coverage`, `halftoneShare`, `maskDimensions`, `downscaleByArea` | — (чистые функции, тестируются без модели и без сети) |
| `src/operations.ts` | Операции поверх одной модели и одних ворот | `makeOperations(gate, getSegmenter, cfg): { cutout, mask }` | вход в очередь и проверка готовности модели — общие для обеих операций |
| `src/layout/request.ts` | Разбор тела `/layout` и быстрый отказ | `parseLayoutRequest(body): request \| invalid \| refused(script \| url)` | формат data-URI кадра, пределы холста, поиск `<script>` и `url(…)` |
| `src/layout/scene.ts` | Страница карточки → сцена в Chromium | `createLayoutRunner({ assetsDir, timeoutMs }): { run(body), close() }` — `run` отдаёт `scene \| invalid \| refused(script \| url \| timeout)` | один браузер на процесс, контекст без JS и без сети на каждый запрос, свои шрифты, код страницы из `assets/layout/extract-browser.js` |
| `src/queue.ts` | «Один инференс за раз» | `makeGate(maxWaiting): <T>(job: () => Promise<T>) => Promise<T>` — отказ бросает `GateBusyError` | счётчик, цепочка промисов |
| `src/http/server.ts` | Контракт HTTP | `createServer(deps): http.Server` | маршрутизация, чтение тела, коды ответов |
| `src/main.ts` | Сборка и порядок старта | — | последовательность: конфиг → сервер (503) → сессия → `ready` |

**Границы, которые нельзя пересекать:**

- `src/cutout/` **не знает** про HTTP: ни запроса, ни ответа, ни кодов. «Выреза нет» выражается
  значением `null`, а не статусом 204 — статус ставит слой HTTP.
- `src/http/` **не знает** про ONNX и Chromium: он получает готовые функции и различает только
  «вырез», «выреза нет», «не разобралось», «занято» и для `/layout` — «сцена» и «отказ (422)».
- `src/layout/` **не знает** про HTTP: отказ выражается значением `refused`, статус 422 ставит
  слой HTTP.
- Секрет живёт **только** в `src/auth.ts`. Ни логгер, ни обработчики ошибок его не видят.
- Ни один модуль не пишет тела запросов/ответов в журнал (`TZ.md` FR-14).

## 5. Интеграции

### Контракт HTTP — уже пообещан вызывающей стороне

Вызывающий код **написан и ждёт именно этого**. Менять контракт в одиночку нельзя: расхождение
обнаружится не тестом, а пустым слоем в оплаченной карточке.

**`GET /health`** — без секрета. 200 `{"status":"ok","ready":true}`; пока модель не
загрузилась — 503 `{"status":"loading","ready":false}`. Ни версии, ни имени модели, ни путей в
ответе быть не должно: проверять живость должен и тот, кто секрета не знает.

**`POST /cutout`**:

| Что | Значение |
| --- | --- |
| Заголовок | `Authorization: Bearer <секрет>` — обязателен |
| `Content-Type` | `image/png` или `image/jpeg` |
| Тело | **сырые байты кадра** — не JSON, не multipart, не base64 |
| Успех | 200, `Content-Type: image/png`, тот же кадр с наложенной альфой, **ровно того же размера в пикселях** |
| Товара не нашлось | **204** без тела — законный ответ, вызывающий молча снимет слой |
| Тело не разбирается как изображение | 400 |
| Секрета нет **или** он неверный | **401 в обоих случаях, одинаково** |
| Тело больше потолка | 413 (ставит nginx) |
| Слишком часто | 429 (ставит nginx) |
| Очередь занята | 503 с `Retry-After` |

**`POST /mask`** — сырые сэмплы альфы для карты занятости кадра. Контракт — ADR-0018 п. 4
родительского проекта (Merch Kit, `../MK/docs/adr/0018-art-director-layout-patch.md`):

| Что | Значение |
| --- | --- |
| Вход, секрет, очередь, коды 400 / 401 / 413 / 429 / 503 | **те же, что у `POST /cutout`**: тот же секрет, те же ворота «один инференс за раз» |
| Товара не нашлось | **204** без тела — тем же кодом, что решает это для `/cutout` (одно суждение «есть ли товар» на весь сервис) |
| Успех | 200, `Content-Type: application/octet-stream`, заголовки `x-mask-width` и `x-mask-height` |
| Тело | ровно `width × height` байт альфы 0…255, построчно сверху вниз |
| Размер | длинная сторона **256**, короткая — `round(256 × короткая / длинная)` по сторонам **кадра** (1440×1920 → 192×256); короткая не меньше 1 |
| Уменьшение | усреднением по площади, **без порога**: мягкая кромка сохраняется (бинаризовать нельзя — тот же запрет, что у маски выреза) |

Берётся альфа в размере кадра до наложения на кадр — та же, что `/cutout` кладёт в четвёртый
канал. Каждая карточка, которой нужна карта, — отдельный инференс: кэша нет.

**`POST /layout`** — сцена страницы карточки, которую сочинила модель родительского продукта:
боксы элементов в px, вычисленные стили и строки текста, как их разложил Chromium (`HtmlScene`).
В слои макета сцену переводит вызывающий, не сервис. Контракт — шаг C2 плана
`html-layout-authoring_2026-10-05.md` родительского проекта:

| Что | Значение |
| --- | --- |
| Секрет, очередь, коды 401 / 429 / 503 | **те же, что у `POST /cutout`**: тот же секрет, те же ворота «одна тяжёлая работа за раз» |
| `Content-Type` | `application/json` (параметры вроде `charset` допускаются), иначе 400 |
| Тело | `{ "html": "<страница>", "canvas": { "width": W, "height": H }, "frame": "data:image/png;base64,…" }` — стороны холста целые 1…4096, кадр — PNG или JPEG data-URI; страница ссылается на кадр как `frame.png` |
| Потолок тела | **2 МиБ** — свой, ниже кадрового; сверх — 413 |
| Успех | 200, `application/json`, сцена `{ canvas, background, elements[], rejected[] }`; непустой `rejected` — тоже 200: решает вызывающий |
| Страница не снимается | **422**, тело `{"reason": "script" \| "url" \| "timeout"}`: `<script>` в HTML; `url(…)` на что-либо, кроме `frame.png`; страница не снялась за 10 с |
| Тело не разбирается | 400 без тела |

HTML — недоверенный ввод. Граница — в браузере, а не в разборе: страница открывается **без JS**
(`javaScriptEnabled: false`) и **без сети** — ответ получают только сам документ, `frame.png` из
тела и свои шрифты (`assets/fonts/`), остальные запросы обрываются. Наружу — только JSON сцены,
никаких снимков экрана. Код внутри страницы — копия общего с родительским продуктом файла
(`assets/layout/extract-browser.js`, пересъёмка — README, раздел «`POST /layout`»).

Ошибка **никогда** не отдаётся телом с внутренностями — ни стека, ни путей, ни имени модели.

### Внешние зависимости рантайма

| Зависимость | Зачем | Что делаем, если недоступна |
| --- | --- | --- |
| Файл весов модели | без него инференса нет | процесс не переходит в `ready`, `/health` остаётся 503; в лог — факт, не путь |
| Chromium Playwright (`playwright` 1.62.1, браузер — `PLAYWRIGHT_BROWSERS_PATH`) | снятие сцены `/layout` | `/layout` отвечает 500, в лог — причина запуска браузера; `/cutout` и `/mask` работают |
| nginx | TLS, потолок тела, ограничение частоты | сервис остаётся доступен только на `127.0.0.1` — то есть недоступен. Это желаемое поведение |

**Секреты и доступы:** `CUTOUT_SECRET` читается из файла окружения с правами `600` на машине.
В git, в логи и в сообщения об ошибках он не попадает никогда. На машине сервиса **нет ни
одного ключа родительского проекта** — [ADR-0006](adr/0006-service-trust-boundary.md).

## 6. Окружения и сборка

| Окружение | Назначение | Чем отличается от прода |
| --- | --- | --- |
| local | разработка и тесты | нет nginx и TLS; секрет — из локального `.env`, не коммитится; веса лежат где угодно по `CUTOUT_MODEL_PATH` |
| prod | боевое | Ubuntu, systemd от непривилегированного пользователя, nginx с TLS перед приложением |

**Конфигурация — только через окружение**, с осмысленными умолчаниями и падением на старте,
если секрета нет:

| Переменная | Что задаёт | Умолчание |
| --- | --- | --- |
| `CUTOUT_SECRET` | общий секрет | **нет — процесс не стартует** |
| `CUTOUT_PORT` | порт на `127.0.0.1` | `8787` |
| `CUTOUT_THREADS` | `intraOpNumThreads` | по числу ядер, но не больше 4 (после четырёх отдача падает) |
| `CUTOUT_MODEL_PATH` | путь к файлу весов | `models/u2netp.onnx` |
| `CUTOUT_ACTIVATION` | чем выход модели превращается в маску: `minmax` или `sigmoid` | `minmax` |
| `CUTOUT_QUEUE_WAITING` | сколько запросов ждут сверх исполняемого | `1` |
| `CUTOUT_MIN_COVERAGE` | ниже этой доли кадра — 204 | `0.01` |
| `CUTOUT_MAX_COVERAGE` | выше этой доли — 204 | `0.99` |

Первые четыре переменные заданы нарядом. Остальные три — параметры развёртывания, а не
контракт: они существуют, чтобы порог «товара нет» и глубину очереди можно было уточнить по
данным первых прогонов, не трогая код.

## 7. Тестирование

**Покрываем обязательно** (`node:test`, без сети и без весов модели):

- контракт авторизации: нет заголовка / неверный секрет → **одинаковый** 401; верный → проход;
- контракт HTTP: `/health` до и после готовности; 400 на неразбираемом теле; 204 на «выреза
  нет»; 503 + `Retry-After` при занятой очереди;
- арифметика маски: сигмоида, порог покрытия <1% / >99%, доля полутона;
- сохранение размера: маска модельного разрешения растягивается к произвольному W×H;
- сохранение RGB: собранный PNG декодируется обратно и совпадает с исходником по RGB.

**Не покрываем автотестами и почему:** реальный инференс — веса в git не идут; качество кромки проверяется вручную на эталонных кадрах при приёмке. В тестах модель подменяется заглушкой, отдающей заданный сырой выход — и логиты, и готовую маску, чтобы обе активации были покрыты.

**Команда прогона:** `npm test`

**Критерии приёмки** живут в [`TZ.md`](TZ.md) §9 — из них сделаны проверки выше.

## 9. Опыт и грабли

### Что уже работало — повторяем

| Решение | Где сработало | Почему повторяем |
| --- | --- | --- |
| Резидентная ONNX-сессия | замер: создание сессии 5,0 с на прежней модели, 0,17 с на `u2netp` | создавать её на запрос — лишняя работа на каждом вырезе |
| `enableCpuMemArena: false` | замер 2026-09-06 на входе 1024: 6,0 ГиБ против 11,9 ГиБ | цена — 10–15% скорости, платится не думая |
| 4 потока инференса | 0,55 с на одном против 0,21 с на четырёх (замер 2026-09-06) | после четырёх отдача пропадает, а память и конкуренция растут |
| `u2netp` вместо `birefnet-general-lite` | 0,55 с против 18,7–22,3 с и 320 МиБ против 6025 МиБ (замер 2026-09-06, один поток) | кромка хуже (полутон 6,2% против 0,2–0,4%) и на 2 эталонных кадрах из 7 модель разваливается — принятая цена, решение владельца 2026-09-06 |

### Что НЕ сработало — не повторяем

| Решение / подход | Что пошло не так | Вывод |
| --- | --- | --- |
| Инференс в изоляте Edge Functions | доступен только однопоточный wasm; инференс **ни разу** не завершился, супервизор снимал его | не возвращаться к изоляту — [ADR-0005](adr/0005-native-onnx-service-over-isolate.md) |
| Инференс в браузере | многопоточность требует заголовков изоляции источника; на iOS память бьёт жёстким отказом при инициализации | не считать вырез на клиенте |
| Генеративная модель вместо сегментации | возвращает новые пиксели — товар смещается, получается двойной контур | нужна альфа для того же растра, а не новая картинка |
| Ограничение веса модели ради браузера | было ограничением браузера и ушло вместе с ним | не квантовать и не уменьшать вход ради скорости **без замера**, показывающего, что кромка не портится |

### Известные грабли стека

| Грабли | Когда всплывают | Что делаем заранее |
| --- | --- | --- |
| **Ловушка активации.** BiRefNet отдаёт **логиты** → маска берётся **сигмоидой**. Семейство U²-Net отдаёт готовую маску 0…1, и там нужна нормировка по крайним значениям | поздно: на логитах нормировка даёт визуально чистую маску, но любая мера мягкости кромки показывает 99,9% полутона; в обратную сторону товар просто перестаёт находиться | способ активации — **свойство модели** (`CUTOUT_ACTIVATION`), а не общий код; сервис проверяет диапазон выхода и падает с понятной ошибкой, а не считает молча |
| Референсная реализация `rembg` применяет **и** сигмоиду, **и** min-max поверх неё | при сверке с чужим кодом возникает соблазн скопировать оба шага | берём **ровно один** шаг, и какой — свойство весов: `u2netp` уже содержит сигмоиду в графе, поэтому только min-max; BiRefNet отдаёт логиты, поэтому только сигмоида |
| `crypto.timingSafeEqual` **бросает** при разной длине буферов | на первом же запросе с секретом другой длины — 500 вместо 401, и сама длина утекает | сравниваются SHA-256-хэши обоих значений: длина всегда 32 байта |
| Арена памяти ORT включена по умолчанию | не на разработке, а в проде под нагрузкой: 12 ГБ и OOM-killer | `enableCpuMemArena: false` + `MemoryMax` в unit — отказ становится предсказуемым и нашим |
| Ресайз маски «примерно» к размеру кадра | вызывающий проверяет размер **по самому файлу** и отвергает ответ как отказ — слой пропадает молча | ресайз к точным W×H исходника + тест на нескольких размерах |
| **`sharp` на одноканальном сыром входе возвращает результат ресайза в ТРЁХ каналах.** `joinChannel` получает буфер втрое длиннее обещанного | не ошибкой, а молча съехавшей на чужой шаг строки альфой: вместо выреза полосы. Поймано только глазами на первом прогоне с настоящими весами | число каналов требуется явно (`toColourspace('b-w')`) и **проверяется** после ресайза; в тестах — проверка геометрии альфы, а не только её гистограммы |
| `sharp` может тронуть цветовое пространство при декодировании | RGB перестаёт совпадать пиксель в пиксель, приём «текст за товаром» рассыпается | декодирование в raw RGB без преобразований, альфа добавляется отдельным каналом, вывод — PNG (без потерь) |

## 11. Handoff: как строить генеральный план

> **Исполнено 2026-09-04.** Работа зашла не через опросник, а через готовый наряд
> [`../PLAN.md`](../PLAN.md) (вход **docs-first**). Оценка по рубрике: цена ошибки высокая
> (расхождение с обещанным контрактом обнаруживается пустым слоем в оплаченной карточке),
> решения по стеку и границе доверия необратимы → **Claude Opus 5, эффорт `high`**.
> Пользователь подтвердил, что эффорт менять не нужно. Активная модель объявлена в начале
> сессии, полоса — доверенная ([ADR-0002](adr/0002-trust-lane-by-model-not-host.md)).

Протокол на будущее (если работа будет переоткрыта другой моделью): прочитать целиком
[`TZ.md`](TZ.md), этот файл, [`VISUALS.md`](VISUALS.md), канон [`../AGENTS.md`](../AGENTS.md) и
карту скилов [`../.claude/skills/INDEX.md`](../.claude/skills/INDEX.md); оценить работу по
рубрике ниже; выдать «модель + эффорт + обоснование» **одной репликой** и **остановиться** до
слова «продолжить». Механика паузы — та же, что в
[`../.claude/commands/review-branches.md`](../.claude/commands/review-branches.md) (шаг 1b).

| Признак работы | Модель | Эффорт |
| --- | --- | --- |
| Генеральный план с нуля: много модулей, необратимые решения, цена ошибки высокая | **Claude Opus 5** (`claude-opus-5`) | `high` → `xhigh` |
| То же, но домен незнакомый / противоречивые требования / длинная автономная проработка | **Claude Fable 5** (`claude-fable-5`) | `xhigh` → `max` |
| Один модуль, стек и границы зафиксированы, решения обратимые | **Claude Sonnet 5** (`claude-sonnet-5`) | `medium` → `high` |
| Механическая работа: переформатировать, разнести по файлам, свести таблицу | **Claude Haiku 4.5** (`claude-haiku-4-5`) | `low` |

Правила выбора — по **самому дорогому** признаку, а не по среднему; эффорт по умолчанию
`high`; модель не понижается ради экономии (это решение пользователя, не модели);
идентификаторы моделей проверять скилом `claude-api`, не по памяти.

**Честная оговорка:** смена модели пользователем машинно не проверяется — как и полосы доверия
в `AGENTS.md`, это держится на самообъявлении.
