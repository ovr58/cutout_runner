## 1. Архитектура

Один процесс Node на выделенной машине. Он держит ONNX-сессию сегментации резидентно в памяти,
принимает **сырые байты кадра** по HTTP от единственного клиента и возвращает **тот же растр**
с наложенным альфа-каналом. Наружу процесс не выпущен: он слушает `127.0.0.1`, а TLS,
ограничение размера тела и ограничение частоты стоят в nginx перед ним. Состояния между
запросами нет — только загруженная модель.

- **Контекст системы** — схема [V-02](VISUALS.md#v-02)
- **Контейнеры** — схема [V-03](VISUALS.md#v-03)
- **Конвейер выреза** — схема [V-04](VISUALS.md#v-04)

**Точка входа:** [`src/main.ts`](../src/main.ts)

**Как запускается (прод):**

```
node dist/main.js
```

**Как запускается (разработка):**

```
npm run dev
```

**Как собирается:**

```
npm ci && npm run build
```

**Как тестируется:**

```
npm test
```

## 2. Стек и обоснование выбора

| Слой | Выбор | Почему именно он | Откатываемо? |
| --- | --- | --- | --- |
| Рантайм | Node 22 LTS | нативный ONNX Runtime доступен как npm-пакет; вызывающий и так живёт в JS-экосистеме | дорого |
| Язык | TypeScript, компиляция `tsc` в `dist/` | контракт из четырёх ответов и тензорные формы — там, где типы окупаются | легко |
| HTTP | `node:http`, **без веб-фреймворка** | два маршрута, тело — сырые байты; фреймворк добавит зависимостей больше, чем кода (Ponytail: stdlib раньше dep) | легко |
| Инференс | `onnxruntime-node` (нативный, **не** `-web`) | wasm-путь измеренно не работает: в изоляте инференс снимает супервизор | дорого — [ADR-0005](adr/0005-native-onnx-service-over-isolate.md) |
| Модель | `birefnet-general-lite` (MIT) | полутон на кромке 0,2–0,4% против 1,5–4,3% у `u2netp`; лицензия допускает коммерческое использование | средне |
| Изображения | `sharp` (libvips) | декодирование PNG/JPEG, ресайз маски Lanczos и сборка RGBA — одной нативной зависимостью вместо трёх чистых JS | средне |
| Тесты | `node:test` (stdlib) | тест-раннер уже в рантайме; jest/vitest здесь ничего не добавляют | легко |
| Сборка/деплой | systemd + nginx на Ubuntu | машина уже существует и настроена; контейнер добавил бы слой без выгоды | легко |

### Рассмотренные альтернативы

| Вариант | Чем был привлекателен | Почему отвергнут |
| --- | --- | --- |
| Инференс в изоляте Supabase Edge Functions | ноль новой инфраструктуры, всё в одном месте | в изоляте доступен только однопоточный wasm; инференс **ни разу не завершился**, его снимал супервизор ([ADR-0005](adr/0005-native-onnx-service-over-isolate.md)) |
| Инференс в браузере пользователя | нулевая стоимость на нашей стороне | многопоточность требует заголовков изоляции источника; на iOS память бьёт жёстким отказом при инициализации |
| Генеративная модель вместо сегментации | «просто перерисовать товар на прозрачном фоне» | вернёт **новые** пиксели: товар сместится, и вместо «текст за курткой» получится двойной контур. Нужна альфа для **того же** растра |
| `u2netp` | быстрее | полутон на кромке 1,5–4,3% против 0,2–0,4%. Оставлен как запасной вариант, если понадобится скорость ценой кромки |
| Express/Fastify | привычно | два маршрута с сырым телом; фреймворк — чистый довесок |
| Ссылка на объект в хранилище вместо байтов кадра | меньше трафика | потребовала бы ключа к хранилищу на машине сервиса — ровно то, что запрещает [ADR-0006](adr/0006-service-trust-boundary.md) |

## 3. Модули и контракты

| Модуль | Ответственность | Что наружу (интерфейс) | Что внутри (скрыто) |
| --- | --- | --- | --- |
| `src/config.ts` | Прочитать и провалидировать окружение при старте | `loadConfig(): Config` — бросает, если нет `CUTOUT_SECRET` | имена переменных, умолчания, разбор чисел |
| `src/logger.ts` | Единственный способ писать в журнал | `log.info/warn/error(event, fields)` | формат строки, поток вывода |
| `src/auth.ts` | Доказательство права звать | `makeAuthorizer(secret): (header?: string) => boolean` | хэширование до фиксированной длины, `timingSafeEqual` |
| `src/model/session.ts` | Жизненный цикл ONNX-сессии | `createSegmenter(cfg): Promise<Segmenter>`; `Segmenter.run(input): Promise<Float32Array>`, `.inputSize` | опции сессии (арена, потоки), имена входа/выхода, форма тензора |
| `src/cutout/pipeline.ts` | Кадр → вырез или «выреза нет» | `computeCutout(bytes, segmenter, cfg): Promise<Buffer \| null>` | препроцесс, активация, ресайз маски, порог покрытия, сборка PNG |
| `src/cutout/mask.ts` | Чистая арифметика маски | `sigmoid`, `toAlphaBytes`, `coverage` | — (чистые функции, тестируются без модели и без сети) |
| `src/queue.ts` | «Один вырез за раз» | `makeGate(maxWaiting): <T>(job: () => Promise<T>) => Promise<T>` — отказ бросает `GateBusyError` | счётчик, цепочка промисов |
| `src/http/server.ts` | Контракт HTTP | `createServer(deps): http.Server` | маршрутизация, чтение тела, коды ответов |
| `src/main.ts` | Сборка и порядок старта | — | последовательность: конфиг → сервер (503) → сессия → `ready` |

**Границы, которые нельзя пересекать:**

- `src/cutout/` **не знает** про HTTP: ни запроса, ни ответа, ни кодов. «Выреза нет» выражается
  значением `null`, а не статусом 204 — статус ставит слой HTTP.
- `src/http/` **не знает** про ONNX: он получает готовую функцию и различает только «вырез»,
  «выреза нет», «не разобралось», «занято».
- Секрет живёт **только** в `src/auth.ts`. Ни логгер, ни обработчики ошибок его не видят.
- Ни один модуль не пишет тела запросов/ответов в журнал (`TZ.md` FR-14).

## 5. Интеграции

### Контракт HTTP — уже пообещан вызывающей стороне

Вызывающий код **написан и ждёт именно этого**. Менять контракт в одиночку нельзя: расхождение
обнаружится не тестом, а пустым слоем в оплаченной карточке.

**`GET /health`** — без секрета. 200 `{"status":"ok","ready":true}`; пока модель не
загрузилась — 503 `{"status":"loading","ready":false}`. Ни версии, ни имени модели, ни путей в
ответе быть не должно: проверять живость должен и тот, кто секрета не знает.

**`POST /cutout`**:

| Что | Значение |
| --- | --- |
| Заголовок | `Authorization: Bearer <секрет>` — обязателен |
| `Content-Type` | `image/png` или `image/jpeg` |
| Тело | **сырые байты кадра** — не JSON, не multipart, не base64 |
| Успех | 200, `Content-Type: image/png`, тот же кадр с наложенной альфой, **ровно того же размера в пикселях** |
| Товара не нашлось | **204** без тела — законный ответ, вызывающий молча снимет слой |
| Тело не разбирается как изображение | 400 |
| Секрета нет **или** он неверный | **401 в обоих случаях, одинаково** |
| Тело больше потолка | 413 (ставит nginx) |
| Слишком часто | 429 (ставит nginx) |
| Очередь занята | 503 с `Retry-After` |

Ошибка **никогда** не отдаётся телом с внутренностями — ни стека, ни путей, ни имени модели.

### Внешние зависимости рантайма

| Зависимость | Зачем | Что делаем, если недоступна |
| --- | --- | --- |
| Файл весов модели | без него инференса нет | процесс не переходит в `ready`, `/health` остаётся 503; в лог — факт, не путь |
| nginx | TLS, потолок тела, ограничение частоты | сервис остаётся доступен только на `127.0.0.1` — то есть недоступен. Это желаемое поведение |

**Секреты и доступы:** `CUTOUT_SECRET` читается из файла окружения с правами `600` на машине.
В git, в логи и в сообщения об ошибках он не попадает никогда. На машине сервиса **нет ни
одного ключа родительского проекта** — [ADR-0006](adr/0006-service-trust-boundary.md).

## 7. Тестирование

**Покрываем обязательно** (`node:test`, без сети и без весов модели):

- контракт авторизации: нет заголовка / неверный секрет → **одинаковый** 401; верный → проход;
- контракт HTTP: `/health` до и после готовности; 400 на неразбираемом теле; 204 на «выреза
  нет»; 503 + `Retry-After` при занятой очереди;
- арифметика маски: сигмоида, порог покрытия <1% / >99%, доля полутона;
- сохранение размера: маска модельного разрешения растягивается к произвольному W×H;
- сохранение RGB: собранный PNG декодируется обратно и совпадает с исходником по RGB.

**Не покрываем автотестами и почему:** реальный инференс — веса в git не идут, а прогон занимает
12–24 с; качество кромки проверяется вручную на эталонных кадрах при приёмке. В тестах модель
подменяется заглушкой, отдающей заданные логиты.

**Команда прогона:** `npm test`

**Критерии приёмки** живут в [`TZ.md`](TZ.md) §9 — из них сделаны проверки выше.

## 9. Опыт и грабли

### Что уже работало — повторяем

| Решение | Где сработало | Почему повторяем |
| --- | --- | --- |
| Резидентная ONNX-сессия | замер 2026-09-03: создание сессии 5,0 с | создавать её на запрос — минус 5 с к каждому вырезу |
| `enableCpuMemArena: false` | замер: 597 МБ против 12 083 МБ | цена — 10–15% скорости, платится не думая |
| 4 потока инференса | 24 / 15,8 / 13,0 / 12,0 с на 1/2/4/8 | после четырёх отдача падает, а память и конкуренция растут |
| `birefnet-general-lite` | полутон на кромке 0,2–0,4% | у `u2netp` 1,5–4,3% — кромка заметна на готовой карточке |

### Что НЕ сработало — не повторяем

| Решение / подход | Что пошло не так | Вывод |
| --- | --- | --- |
| Инференс в изоляте Edge Functions | доступен только однопоточный wasm; инференс **ни разу** не завершился, супервизор снимал его | не возвращаться к изоляту — [ADR-0005](adr/0005-native-onnx-service-over-isolate.md) |
| Инференс в браузере | многопоточность требует заголовков изоляции источника; на iOS память бьёт жёстким отказом при инициализации | не считать вырез на клиенте |
| Генеративная модель вместо сегментации | возвращает новые пиксели — товар смещается, получается двойной контур | нужна альфа для того же растра, а не новая картинка |
| Ограничение веса модели ради браузера | было ограничением браузера и ушло вместе с ним | не квантовать и не уменьшать вход ради скорости **без замера**, показывающего, что кромка не портится |

### Известные грабли стека

| Грабли | Когда всплывают | Что делаем заранее |
| --- | --- | --- |
| **Ловушка активации.** BiRefNet отдаёт **логиты** → маска берётся **сигмоидой**. Семейство U²-Net отдаёт готовую маску, и там нужна нормировка по крайним значениям | поздно: на логитах нормировка даёт визуально чистую маску, но любая мера мягкости кромки показывает 99,9% полутона | способ активации — **свойство модели**, а не общий код: он задан рядом с моделью и покрыт тестом на долю полутона |
| Референсная реализация `rembg` применяет **и** сигмоиду, **и** min-max поверх неё | при сверке с чужим кодом возникает соблазн скопировать оба шага | берём **только** сигмоиду: замеренные 0,2–0,4% получены так; лишняя min-max растягивает уже насыщенный диапазон |
| `crypto.timingSafeEqual` **бросает** при разной длине буферов | на первом же запросе с секретом другой длины — 500 вместо 401, и сама длина утекает | сравниваются SHA-256-хэши обоих значений: длина всегда 32 байта |
| Арена памяти ORT включена по умолчанию | не на разработке, а в проде под нагрузкой: 12 ГБ и OOM-killer | `enableCpuMemArena: false` + `MemoryMax` в unit — отказ становится предсказуемым и нашим |
| Ресайз маски «примерно» к размеру кадра | вызывающий проверяет размер **по самому файлу** и отвергает ответ как отказ — слой пропадает молча | ресайз к точным W×H исходника + тест на нескольких размерах |
| `sharp` может тронуть цветовое пространство при декодировании | RGB перестаёт совпадать пиксель в пиксель, приём «текст за товаром» рассыпается | декодирование в raw RGB без преобразований, альфа добавляется отдельным каналом, вывод — PNG (без потерь) |

| Один модуль, стек и границы зафиксированы, решения обратимые | **Claude Sonnet 5** (`claude-sonnet-5`) | `medium` → `high` |
| Механическая работа: переформатировать, разнести по файлам, свести таблицу | **Claude Haiku 4.5** (`claude-haiku-4-5`) | `low` |

Правила выбора — по **самому дорогому** признаку, а не по среднему; эффорт по умолчанию
`high`; модель не понижается ради экономии (это решение пользователя, не модели);
идентификаторы моделей проверять скилом `claude-api`, не по памяти.

**Честная оговорка:** смена модели пользователем машинно не проверяется — как и полосы доверия
в `AGENTS.md`, это держится на самообъявлении.
