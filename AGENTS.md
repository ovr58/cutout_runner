# cutout_runner — канон правил для всех AI-агентов

> **Это источник истины по кросс-AI правилам.** При расхождении между этим файлом и любым
> файлом-адаптером (`CLAUDE.md`, `.github/copilot-instructions.md`) прав этот файл.
>
> Читают: **Harvi Code** — автозагружает этот файл в каждую сессию · **Claude Code** — через
> `@AGENTS.md`-импорт в `CLAUDE.md` · **GitHub Copilot** — через выжимку в
> `.github/copilot-instructions.md` (импортов не поддерживает).
>
> Держать коротким: файл всегда в контексте. Детали — по ссылкам.

## О проекте

- **Стек:** Node 22 LTS · TypeScript (`tsc` → `dist/`) · `node:http` без веб-фреймворка · `onnxruntime-node` (нативный ORT, модель `birefnet-general-lite`) · `sharp`/libvips · `node:test` · развёртывание systemd + nginx на Ubuntu
- **Архитектура (обзор):**
  `src/main.ts` (порядок старта) → `src/http/server.ts` (два маршрута, сырые байты) →
  `src/queue.ts` (ворота «один вырез за раз») → `src/cutout/` (кадр → альфа, без знания об HTTP) →
  `src/model/session.ts` (резидентная ONNX-сессия, арена памяти выключена).
  Слушает только `127.0.0.1`; наружу выпускает nginx с TLS. Состояния между запросами нет.
  Схемы — `docs/VISUALS.md` [V-03](docs/VISUALS.md#v-03), [V-04](docs/VISUALS.md#v-04).

## Что умеет твой хост (и чего не умеет)

**AI-хост** — среда, в которой ты исполняешься (Claude Code / Harvi Code / Copilot). Хост ≠
модель: в одном хосте бывают разные модели, а одна модель доступна в разных хостах.

| Возможность | Claude Code | Harvi Code | Copilot |
| --- | --- | --- | --- |
| Автозагрузка правил | `CLAUDE.md` (+ `@import`) | `AGENTS.md`, `AGENTS.local.md` | `.github/copilot-instructions.md`, `.github/instructions/*` по `applyTo` |
| Нативные слэш-команды | `.claude/commands/` | **нет** — читать файл по пути | `.github/prompts/` |
| Автообнаружение скилов | `.claude/skills/` | **нет** — читать по пути | **нет** |
| Субагенты | Agent + `.claude/agents/` | `new_task` | `.github/agents/` |
| Hooks | `.claude/settings.json` | **нет** | **нет** |
| Долгая память вне репо | `~/.claude/projects/<…>/memory/` | **нет** | **нет** |
| MCP (Model Context Protocol) | да | да | да |

**Не обещай того, чего у твоего хоста нет.** Если у тебя нет автообнаружения скилов — ты не
«знаешь скилы», ты обязан открыть файл по пути. Если нет долгой памяти — не ссылайся на неё.

## Полосы доверия — по модели, а не по хосту

Полное обоснование — [`docs/adr/0002-trust-lane-by-model-not-host.md`](docs/adr/0002-trust-lane-by-model-not-host.md).

**Объяви активную модель в начале сессии** — от этого зависит твоя полоса. Не можешь
подтвердить, что работаешь на Opus → консервативная полоса.

**Доверенная полоса — только Opus** (в любом хосте: Claude Code или Harvi Code):
- ветки `claude/<slug>` или `harvi/<slug>`, планы без суффикса;
- self-review разрешён, fast-merge в `main` после него — тоже;
- обязан выступать ревьюером для веток консервативной полосы.

**Консервативная полоса — любая не-Opus модель** (Sonnet, Copilot, DeepSeek и пр.):
- ветки `feature/<slug>` · `fix/<slug>` · `exp/<slug>`;
- планы с суффиксом производителя: `_harvi_`, `_copilot_`, `_claude_<model-slug>_`;
- **self-approve запрещён**; готовишь review-handoff и ждёшь ревью Opus + явного апрува
  пользователя;
- **review-handoff** = изменённые файлы · цель · риски · ручные проверки · готовый промпт для
  ревьюера. Писать под «холодного» ревьюера, без опоры на текущий диалог.

**Хард-правила для всех полос:**
- **Никаких прямых коммитов в `main`/`master`** — pre-commit hook блокирует
  (`githooks/pre-commit`), на GitHub дублируется branch protection.
- **Пуш и деплой — только по явной команде пользователя.** Всегда, включая доверенную полосу.
- Slug ветки — 2–5 слов через дефис, на английском.

> Правило про модель машинно не проверяется: ни хук, ни CI (Continuous Integration —
> автосборка/автопроверки на сервере) не знают, какая модель активна. Держится на твоём
> самообъявлении. Не выдавай это за гарантию.

## Consult-first: сверься со скилами перед действием

**Перед нетривиальным действием** (план, отладка, TDD, ревью, работа с ветками, решение
спавнить субагента) открой карту скилов [`.claude/skills/INDEX.md`](.claude/skills/INDEX.md),
найди подходящий по триггеру и следуй его `SKILL.md`.

**Каталог `.claude/` — host-neutral склад методики для ВСЕХ хостов.** Имя каталога — артефакт
автообнаружения Claude Code, а не признак принадлежности. Harvi и Copilot читают эти файлы по
явному относительному пути — обычный markdown, никакой магии. То же для
[`.claude/commands/`](.claude/commands/): у тебя может не быть нативной `/`-команды, но
процедура в файле исполнима как есть. Обоснование —
[`docs/adr/0001-agents-md-canon-without-ai-layer.md`](docs/adr/0001-agents-md-canon-without-ai-layer.md).

Новый скил заводится по скилу `writing-skills` + строка в `INDEX.md` в том же изменении.

## Планы: lifecycle и навигация

| Папка | Что внутри |
| --- | --- |
| `planning/INDEX.md` | **Карта**: одна строка на файл. Читать ЕЁ, а не сканировать папки. |
| `planning/BACKLOG.md` | Предтечи планов: готовые промпты+референсы для будущих сессий. |
| `planning/reference/` | Вечнозелёные блюпринты и справочники. |
| `planning/active/` | Планы/баги в работе. «Что активно?» — отвечать ОТСЮДА + INDEX. |
| `planning/archive/{reviews,bugs,plans,runs}/` | История. Не опираться как на актуальный факт. |

`BACKLOG` → `Draft` → `ACTIVE` (`planning/active/`, шапка `Status: ACTIVE (с YYYY-MM-DD)`) →
`DONE` (шапка + блок «Что реально сделано») → `ARCHIVED` (`planning/archive/plans/`).

**Любое перемещение/добавление плана обновляет одну строку в `planning/INDEX.md` в том же
изменении.** Процедуры — `.claude/commands/plan-new.md`, `plan-status.md`, `plan-archive.md`.

**Развилки → backlog.** Предложение, тянущее на отдельный план будущей сессии — не терять:
запись в `planning/BACKLOG.md` = готовый промпт + референсы, работающий «холодным».

**Spec-first: перед генеральным планом должны существовать ТЗ и спецификация.**
`planning/reference/00_GENERAL_PLAN.md` строится **из** [`docs/TZ.md`](docs/TZ.md) (что и
зачем) + [`docs/SPEC.md`](docs/SPEC.md) (как) + [`docs/VISUALS.md`](docs/VISUALS.md) (схемы и
референсы — **единственный** визуальный артефакт, переписывается на месте, дублёров не
заводить). Их нет — сначала интейк по скилу
[`spec-intake`](.claude/skills/spec-intake/SKILL.md), а не план по догадкам. Пробел в
артефакте помечается `> TODO(пользователь):`, а не додумывается. Решения — ADR-0003, ADR-0004.

## Единый язык и решения

- **Доменные термины** — в [`CONTEXT.md`](CONTEXT.md): один термин = одно согласованное
  значение. Новый термин фиксируй туда, не плоди синонимы.
- **Сокращения и жаргон** — при **первом** употреблении расшифровывай в скобках. Сокращения —
  **всегда** (WS → WebSocket); понятие — если его может не понять джуниор. Словарь —
  [`docs/GLOSSARY.md`](docs/GLOSSARY.md): сверяйся перед вводом, новое добавляй строкой.
- **Необратимые/дорогие-к-откату решения** — один файл на решение в
  [`docs/adr/`](docs/adr/README.md). Обратимое остаётся в плане/PR. Историю не переписываем:
  устаревшее решение *supersede*-им новым ADR (Architecture Decision Record).

## Работа с кодом

- **Минимальные правки:** 1 баг = 1 правка в 1 месте. Не рефакторить «заодно», не добавлять
  абстракции «на будущее». Не трогать рабочие тесты.
- **Читать затронутый код целиком** до фикса и опираться на реальные данные (логи,
  воспроизведение), а не на догадки.
- Конвенции по областям — `.github/instructions/*.instructions.md` (активируются по
  `applyTo`-глобу в Copilot; в других хостах — читать по пути).
- **Ponytail** (ленивый сеньор: YAGNI → reuse → stdlib → native → dep → one-liner) —
  `.github/instructions/ponytail.instructions.md`, детали в `docs/PONYTAIL_SETUP.md`.
  **Лестница прогоняется по умолчанию, а не по напоминанию.** Плагин Claude Code не
  подмешивает себя в каждый ход, а у Harvi и Copilot плагина нет вовсе — «сработает само» не
  сработает никогда. Это то же правило, что «минимальные правки» выше, только с порядком
  проверок. Понизить строгость проект может, но это решение владельца, записанное явно.
- Логирование — только через логгер проекта, не `print`/`console.log` в проде.
- **Секреты — никогда в коде и в git** (см. `.gitignore`).

## Отчётность и затраты

Полные правила — [`docs/WORKING_RULES.md`](docs/WORKING_RULES.md). Переносимый минимум:

- **Действуй при достаточной информации.** Не докладывай micro-steps, не перечисляй варианты,
  которые не будешь делать. Независимые операции — параллельно.
- **Честно:** падения/зависания — немедленно, с выводом; докладывать только новое; сделано и
  проверено — заявлять прямо, пропущено — сказать.
- **Лимиты вывода:** результат инструмента ≤50 строк; запросы к данным — с `LIMIT`; логи —
  хвост с фильтром шума, не файл целиком.
- **Мониторинг длительных прогонов — низкошумный:** редкий опрос с длинным интервалом вместо
  плотного поллинга, ≤30 событий в час. Не опрашивать ради опроса. Конкретные инструменты —
  в файле-адаптере твоего хоста.
- **Субагенты — осознанно.** Холодный субагент дорог: заново выводит уже имеющийся контекст.
  По умолчанию inline; спавн — только под широкий fan-out, настоящую параллельность, изоляцию
  шумного контекста или явную просьбу. Модель — по сложности задачи. Гейт — скилы
  `subagent-driven-development` и `dispatching-parallel-agents`.
