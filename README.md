# cutout_runner

HTTP-сервис, который по кадру карточки товара возвращает **тот же самый растр** с прозрачным
фоном — слой `cutout`.

Родительский продукт собирает карточки для маркетплейсов: модель изображений рисует сцену, а
вёрстку — заголовок, характеристики, плашки — ставит своя программа поверх. Слой `cutout` — это
тот же кадр, положенный **вторым слоем поверх текста**, чтобы текст уходил за товар. Приём
работает ровно потому, что оба слоя — один растр, пиксель в пиксель. Значит нужна не новая
картинка, а **альфа для того же растра**: задача сегментации, а не генерации.

Сервис держит ONNX-модель `u2netp` резидентно в памяти и считает нативным ONNX
Runtime на отдельной машине. Почему не в изоляте и не в браузере — [ADR-0005](docs/adr/0005-native-onnx-service-over-isolate.md).

> **Репозиторий публичный.** В нём нет и не должно появиться: адреса машины, секрета, весов
> модели. Всё это приходит файлом окружения на машине, где сервис работает, и передаётся
> отдельно от репозитория. Граница доверия — [ADR-0006](docs/adr/0006-service-trust-boundary.md):
> **на машине сервиса нет ни одного ключа родительского проекта.**

## Контракт

Вызывающий один — Edge Function родительского продукта, и её код **уже написан и ждёт именно
этого**. Менять контракт в одиночку нельзя: расхождение обнаружится не тестом, а пустым слоем
в оплаченной карточке. Полностью — [`docs/SPEC.md`](docs/SPEC.md) §5.

### `GET /health` — без секрета

`200 {"status":"ok","ready":true}` · пока модель грузится (~5 с) — `503 {"status":"loading","ready":false}`.
Ни версии, ни имени модели, ни путей в ответе нет: живость проверяет и тот, кто секрета не знает.

### `POST /cutout`

| Что | Значение |
| --- | --- |
| Заголовок | `Authorization: Bearer <секрет>` — обязателен |
| `Content-Type` | `image/png` или `image/jpeg` |
| Тело | **сырые байты кадра** — не JSON, не multipart, не base64 |
| Успех | `200`, `image/png`, тот же кадр с альфой, **ровно того же размера в пикселях** |
| Товара не нашлось | **`204`** без тела — законный ответ, вызывающий снимет слой |
| Тело не разбирается как изображение | `400` |
| Секрета нет **или** он неверный | **`401` в обоих случаях, одинаково** |
| Тело больше потолка · слишком часто | `413` · `429` (ставит nginx) |
| Очередь занята | `503` с `Retry-After` |

**204 — штатный исход, а не авария:** слой `cutout` есть у 4 макетов из 34. Сервис обязан честно
говорить «нет», а не выдумывать маску.

Тело ошибки **никогда** не содержит внутренностей — ни стека, ни путей, ни имени модели.

## Запуск (разработка)

```bash
npm ci
npm test                       # 47 проверок; весов модели и сети не требуют
npm run build

bash deploy/fetch-model.sh ./models       # веса + текст лицензии MIT, с проверкой MD5

CUTOUT_SECRET=$(openssl rand -hex 32) npm start
curl -s http://127.0.0.1:8787/health
```

Сервис слушает **только `127.0.0.1`**: наружу его выпускает исключительно nginx, и ошибка в
конфигурации приложения не открывает его в интернет.

### Конфигурация — только через окружение

| Переменная | Что задаёт | Умолчание |
| --- | --- | --- |
| `CUTOUT_SECRET` | общий секрет | **нет — процесс не стартует** |
| `CUTOUT_PORT` | порт на `127.0.0.1` | `8787` |
| `CUTOUT_THREADS` | `intraOpNumThreads` | по числу ядер, но не больше 4 |
| `CUTOUT_MODEL_PATH` | путь к весам | `models/u2netp.onnx` |
| `CUTOUT_ACTIVATION` | чем выход модели превращается в маску: `minmax` или `sigmoid` | `minmax` |
| `CUTOUT_QUEUE_WAITING` | ожидающих сверх исполняемого | `1` |
| `CUTOUT_MIN_COVERAGE` / `CUTOUT_MAX_COVERAGE` | порог «товара нет» | `0.01` / `0.99` |

Образец файла окружения — [`deploy/cutout-runner.env.example`](deploy/cutout-runner.env.example)
(значения подставные).

## Устройство

```
src/main.ts          порядок старта: конфиг → сокет 127.0.0.1 (503) → сессия ORT → ready
  http/server.ts     два маршрута, сырые байты; про ONNX не знает
  queue.ts           ворота «один вырез за раз», сверх очереди — 503 + Retry-After
  cutout/pipeline.ts кадр → альфа; про HTTP не знает («выреза нет» = null, а не 204)
  cutout/mask.ts     чистая арифметика: сигмоида, покрытие, доля полутона
  model/session.ts   резидентная ONNX-сессия, арена памяти выключена
  auth.ts            timingSafeEqual над SHA-256; секрет живёт только здесь
  config.ts          окружение; без CUTOUT_SECRET процесс не стартует
  logger.ts          единственный способ писать в журнал; тела не логируются
```

Схемы — [V-03](docs/VISUALS.md#v-03) (контейнеры), [V-04](docs/VISUALS.md#v-04) (конвейер
выреза), [V-05](docs/VISUALS.md#v-05) (граница доверия).

## Три грабли, которые дороже всего

Полный список — [`docs/SPEC.md`](docs/SPEC.md) §9. Эти три не дают ошибки в логе: брак виден
только на готовой карточке.

1. **Активация.** Чем выход модели превращается в маску — **свойство весов**, а не общий код:
   `u2netp` (семейство U²-Net) отдаёт готовую маску 0…1 и требует нормировки по крайним
   значениям (`minmax`), BiRefNet отдаёт **логиты** и требует **сигмоиды**. Перепутать —
   99,9% полутона на кромке вместо 0,2–0,4% либо мгновенная потеря товара. Задаётся
   `CUTOUT_ACTIVATION`; сервис проверяет диапазон выхода и падает с понятной ошибкой.
2. **Арена памяти ORT** включена по умолчанию: на входе 1024 пик **11,9 ГиБ** против **6,0 ГиБ**
   без неё. `enableCpuMemArena: false` обязателен, и проверяется он **замером пика памяти**
   (`VmHWM`), а не чтением кода и не выборкой `rss` — выборка не видит всплеск внутри
   блокирующего `session.run()` и уже занижала результат в 16 раз.
3. **Число каналов маски.** `sharp` на одноканальном сыром входе возвращает ресайз в трёх
   каналах; `joinChannel` получает буфер втрое длиннее обещанного, альфа съезжает на чужой шаг
   строки — полосы вместо выреза, без единого исключения. Требуется явный `toColourspace('b-w')`
   и проверка `info.channels`.

## Замеры

Машина разработки, 16 ядер, 4 потока инференса, кадр 1440×1920:

| Что | Число |
| --- | --- |
| Загрузка сессии ORT | 0,17 с — сессия всё равно создаётся **один раз при старте** |
| Инференс (1 / 4 потока) | 0,55 / 0,21 с |
| Пик памяти процесса | 320 МиБ (`PeakWorkingSet64`, арена выключена) |
| Полутон на кромке | 6,2% — **мерой качества не является**, см. ниже |

Числа сняты 2026-09-06 тем же способом, что и у прежней модели `birefnet-general-lite`
(18,7–22,3 с и 6025 МиБ на одном потоке), поэтому сравнимы напрямую.

Доля полутона ловит **перепутанную активацию**, а не качество выреза: пустая маска даёт
идеальные 0%. Качество `u2netp` ниже: на 5 эталонных кадрах из 7 вырез приличный, на двух
модель разваливается. Это принятая цена скорости — разбор в плане B19 родительского проекта.

## Развёртывание

Ubuntu, systemd от непривилегированного пользователя, за nginx с TLS. Пошагово —
[`deploy/README.md`](deploy/README.md). Лимиты (потолок тела, частота) стоят в nginx, а не в
приложении: запрос, отбитый до Node, не занимает ни ядра, ни памяти инференса.

## Лицензии

Веса модели `u2netp` ([U-2-Net](https://github.com/xuebinqin/U-2-Net)) — **особый случай, и это
надо знать до коммерческого запуска.** Файл `LICENSE` в репозитории U-2-Net (Apache-2.0)
покрывает **код**; веса лежат вне репозитория, и README отправляет за разрешением к авторам
письмом. Владелец написал и 2026-09-06 получил **предварительное** согласие на коммерческое
использование, детали оговариваются при запуске. Риск **отложен, а не закрыт**: разрешение с
явными условиями надо получить до коммерческого запуска.

В git веса не идут: репозиторий публичный. `deploy/fetch-model.sh` скачивает их вместе с текстом
лицензии и проверяет контрольную сумму. Прежняя модель `birefnet-general-lite` — MIT и на код, и
на карточку модели; она осталась рабочим запасным вариантом, если согласие сорвётся (правится
`CUTOUT_MODEL_PATH` + `CUTOUT_ACTIVATION=sigmoid` и лимиты памяти в unit).

> Лицензия на код самого сервиса не выбрана: файла `LICENSE` в репозитории нет, а значит по
> умолчанию действует «все права защищены». Для публичного репозитория это стоит решить явно.
