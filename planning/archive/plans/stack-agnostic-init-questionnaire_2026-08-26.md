## Context

Шаблон сейчас неявно заточен под один профиль проекта: `INIT.md` шаг 3 переименовывает
**один** файл `.github/instructions/python.instructions.md`, `tools/ui-audit/` — WinUI/FlaUI,
плейсхолдер `{{LANGUAGE}}` единственного числа. Для React / React Native / Xcode-iOS и прочих
стеков это не разворачивается без ручной переделки.

Вторая дыра — **вход в проект**. `INIT.md` шаг 2 спрашивает плейсхолдеры (имя, стек,
архитектура), но не выясняет **что именно строим**. Если у пользователя уже есть ТЗ или
спецификация — они не используются; если есть только референс («хочу как вот этот сайт») —
некуда положить; если нет ничего — нет процедуры, которая доведёт до ТЗ. В итоге
`planning/reference/00_GENERAL_PLAN.md` (генеральный план) составляется из воздуха.

Третья дыра — **передача в планирование**. Модель, которая будет строить генеральный план по
докам, не получает подсказки, каким сочетанием модель+эффорт это делать, и не делает паузу,
чтобы пользователь успел переключиться. Механика паузы в шаблоне уже есть — в
`.claude/commands/review-branches.md`; её надо переиспользовать, а не изобретать.

Ожидаемый исход: `INIT.md` разворачивает шаблон на любом стеке, а перед первой строкой кода в
`docs/` лежат ТЗ и спецификация, доработанные интервью и годные как вход для генерального
плана.

## Цель

Сделать инициализацию шаблона стек-агностичной и spec-first: три входа (готовые доки в
`docs/` · референс-приложение · опросник с нуля), модульный опросник по индустриальным
стандартам, генерация `docs/TZ.md` + `docs/SPEC.md` с обязательным handoff-блоком
(рекомендация модели/эффорта + пауза на переключение) и с применением наличных скилов для
вытягивания информации, референсов и **удачного И неудачного** прошлого опыта.

**Визуальный артефакт `docs/VISUALS.md`** — третий обязательный артефакт интейка наряду с ТЗ и

артефакт по строгому правилу **переписывается на месте** и остаётся единственным результатом
без дублёров.

Реализуется в Э3 (шаблон + правило единственности), Э2 (вопросы, порождающие визуалы), Э4
