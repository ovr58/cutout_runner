# Кросс-AI исполнение правил: Harvi Code + надзор Opus

Status: DONE (выполнено 2026-08-26)

Supersedes: `planning/active/cross-ai-template-upgrade_2026-08-26.md` — черновик Harvi Code,
взят как источник входных данных; часть решений пересмотрена (см. «Что взято, что отвергнуто»).

## Context

Темплейт спроектирован вокруг Claude Code: `CLAUDE.md` автозагружается, `.claude/skills/`
автообнаруживаются, память живёт вне репозитория. Появился третий хост — **Harvi Code**
(VS Code-расширение, AI-агент с выбором модели, включая Opus). Copilot уже присутствует
зеркалом.

Проблема не в том, что у хостов разные возможности, а в том, что **правило, которое хост
физически не получает в контекст, не исполняется** — при этом документ утверждает обратное.
Проверка нашла ровно такой случай уже сейчас (см. Ф3).

**Критерий приоритета (задан пользователем):** выбирать схему по тому, насколько она
**заставляет правила исполняться**; надзорная функция — **главенство Opus над остальными
моделями**. Симметрия хостов и «красота» раскладки — вторичны, число копий — третично.

## Цель

Привести Claude Code, Harvi Code и Copilot к одному исполняемому своду правил с единой
дисциплиной веток и моделей, где Opus — надзорная модель для всех остальных, и где каждый
заявленный механизм автозагрузки подтверждён, а не предположен.

## Проверенные факты (матрица возможностей хостов)

| Возможность | Claude Code | Harvi Code | Copilot |
| --- | --- | --- | --- |
| Автозагрузка правил проекта | `CLAUDE.md` (+ `@import`) ✅ | `AGENTS.md` / `AGENTS.local.md` ⚠️ | `.github/copilot-instructions.md` + `.github/instructions/*` по `applyTo` ✅ |
| Читает `AGENTS.md` | **нет** ✅ проверено | да ⚠️ | нет |
| Нативные слэш-команды | `.claude/commands/` ✅ | нет — чтение файла по пути ⚠️ | `.github/prompts/` ✅ |
| Автообнаружение скилов | `.claude/skills/` ✅ | нет | нет |
| Субагенты | Agent + `.claude/agents/` ✅ | `new_task` ⚠️ | `.github/agents/` |
| Hooks | `.claude/settings.json` ✅ | нет данных | нет |
| Долгая память вне репо | `~/.claude/projects/<…>/memory/` ✅ | нет | нет |
| MCP (Model Context Protocol) | ✅ | заявлено на маркетплейсе | ✅ |

✅ — проверено · ⚠️ — самоотчёт Harvi, требует подтверждения (шаг 0).

**Ф1.** Claude Code **не** читает `AGENTS.md` — только `CLAUDE.md`. Ходовое утверждение
«читает как fallback» не подтверждается документацией. Значит `CLAUDE.md` обязан остаться
реальным файлом, а связь с каноном — через `@import`.
**Ф2.** `CLAUDE.md` поддерживает `@path`-импорты → канон можно держать в одном месте без
копипасты текста.
**Ф3 (баг).** `.github/claude-instructions.md` **не подхватывается Copilot** — автозагружаемое
имя `.github/copilot-instructions.md`. Шапка файла при этом утверждает «автоматически попадает
в контекст Copilot». Правило заявлено, но не исполняется — ровно тот класс дефекта, против
которого этот план.
**Ф4 — снята как ошибочная (2026-08-26).** Изначально записал `{{YYYY-MM-DD}}` в
`planning/INDEX.md:10` и `.claude/skills/INDEX.md:9` как дефект. Это неверно: `INIT.md` шаг 2
явно перечисляет их среди плейсхолдеров, заполняемых при инициализации проекта, — такая же
намеренная механика шаблона, как `{{DOMAIN}}` или `{{STACK}}`. Ничего не чиню.

## Принятые решения

**Р1. Канон — `AGENTS.md`, слой `.ai/` не заводим.** → ADR-0001.
Обоснование по критерию: у Harvi нет ни автообнаружения скилов, ни нативной регистрации
команд — он в любом случае читает markdown по явно указанному пути. Путь `.ai/skills/INDEX.md`
и путь `.claude/skills/INDEX.md` для него **равноценны по исполняемости**; разница только в
том, что первый требует третьей копии ~20 скилов и 6 команд. Три расходящиеся копии делают
вопрос «какая из них правило?» неразрешимым — это прямой ущерб исполнению правил, а не
нейтральная цена. `.claude/` объявляется host-neutral складом методики; имя каталога — артефакт
автообнаружения Claude Code, а не признак принадлежности.

**Р2. Полоса доверия — по модели, не по хосту.** → ADR-0002.
Opus в любом хосте (Claude Code или Harvi) — **доверенная полоса**: self-review, право
ревьюить чужие ветки. Любая не-Opus модель (Sonnet, Copilot, DeepSeek и пр.) — **консервативная
полоса**: ревью от Opus + явный апрув пользователя перед мёржем. Если хост не может
подтвердить активную модель — консервативная полоса по умолчанию.

**Р3. Fast-merge сохраняется, но привязывается к модели, а не к хосту.** Предложение Harvi
удалить его целиком отклонено: правило введено осознанно, а заявленное им противоречие с
`docs/WORKING_RULES.md` §7 мнимое — §7 говорит о внешних/публикующих действиях (пуш, деплой),
а не о локальном мёрже в main. Fast-merge остаётся привилегией доверенной полосы.

## Что взято из плана Harvi, что отвергнуто

**Взято:** `AGENTS.md` как канон · тонкие entrypoint-файлы на хост · честное разделение
«нативная интеграция vs процедурный эквивалент» · запрет обещать Harvi несуществующие
рантайм-фичи · fallback на консервативную полосу при неподтверждённой модели · review-handoff
(изменённые файлы, цель, риски, ручные проверки, готовый промпт для ревьюера) · `harvi/<slug>`
в списке боковых веток · отказ от генератора ради устранения дублирования.

**Отвергнуто:** слой `.ai/` (Р1) · удаление fast-merge (Р3) · привязка доверия к хосту
Claude Code вместо модели (Р2) · перенос `memory-seed/` в `.ai/` с оставлением зеркала —
это дублирование без выигрыша в исполняемости.

**Исправлено:** план Harvi называл `.github/claude-instructions.md` рабочим Copilot-входом
и планировал его сохранить — файл не автозагружается (Ф3).

## Риски

1. **Самоотчёт Harvi может быть неточен.** Всё держится на автозагрузке `AGENTS.md`. Митигация —
   гейт-шаг 0 до любых правок.
2. **`@import` в `CLAUDE.md` может не развернуться** — тогда Claude Code теряет весь свод
   кросс-AI правил разом. Митигация — проверка в шаге 2 с явным откатом на дублирование.
3. **Полоса по модели не проверяема машинно.** Ни хук, ни CI не знают активную модель —
   исполнение держится на самообъявлении и на ревью Opus. Честно зафиксировать это в ADR-0002,
   а не изображать гарантию.
4. **`.claude/` как host-neutral канон контринтуитивен.** Следующая сессия Harvi, увидев имя
   каталога, снова предложит `.ai/`. Митигация — ADR-0001 как готовый ответ на переоткрытие.

## Не делать в рамках этого плана

- Не заводить генератор/скрипты синхронизации ради устранения markdown-дублирования.
- Не удалять адаптеры `.claude/` или `.github/`.
- Не коммитить, не мёржить, не пушить без явной команды пользователя.
